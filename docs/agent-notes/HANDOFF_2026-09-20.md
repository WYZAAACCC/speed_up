## §3 🔴 本轮结论：**「靠 AMR 把晶界加密到接近真实尺寸」这条路走不通**

> 这是本轮最后一个、也是最重要的结论。**用户明确问过两次**，
> **下次很可能再问，请直接引用本节，不要重跑。**

### 3.1 用户的问题

> 「现在不是已经有了 AMR 吗，能不能将晶界划分到足够高的精度，接近真实的尺寸，
> 但是因为晶界本身占体积不多，因此网格数量也不会上升太多？」
>
> 「有没有只加密晶界网络。晶界网格的尺寸足够小就能将厚度降下来，
> 而晶粒与其他的部分网格尺寸不变可以吗？」

### 3.2 第一件事：**AMR 加密的是网格，不是晶界**

晶界的宽度**不是网格决定的，是模型参数决定的**。
看生产 `pipeline/stage1_meltpool_c.i` 的 `[free_energy]`（约 796–806 行）：

```
f_loc = k_c/2*(c-c0)^2
      + A_part*c^2*min(1,2S)
      + (Omega0/wgb)*(c-c0)*h_gb            ← 偏析阱
h_gb  = 8*(S^2 - Q),  S = Ση_i²,  Q = Ση_i⁴
```

`h_gb` 的**宽度就是 η 界面的宽度 = `int_width` = 4 µm**。
**AMR 开到 100 级，它还是 4 µm。** 加密只能把剖面画得更清楚，不能画得更窄。

**⇒ 加密策略本身是对的**（生产现在就是用 `S=Ση²` 的梯度跳变做指示量，
**只加密晶界网络 + 固液前沿，不碰晶粒内部**，代价仅 +55% 单元，
2026-09-19 已合入，见 `VALIDATION_STATUS.md` §1.6）。
**但它单独做，一分物理都不涨。**

### 3.3 那什么决定厚度 —— 一个闭式

因为 `c(z)` 对 `h_gb` 是**线性**的，剖面形状完全不参与，只有 `h_gb` 的峰值（= 4）起作用：

```
s − 1 = 4·|Ω₀| / ( wgb · (k_c + 2·A_part) · c_S )
      = 6.173e-9 / wgb          [wgb 单位 m]
```

脚本：**[`pipeline/validated/gb_width_vs_s.py`](../../pipeline/validated/gb_width_vs_s.py)**（纯解析，秒级，无依赖）

| `wgb` | `int_width` | `s` |
|---|---|---|
| **4 µm（生产现状）** | 8 µm | **1.0015** |
| 100 nm | 200 nm | 1.06 |
| 10 nm | 20 nm | 1.62 |
| **2 nm** | 4 nm | **4.09** ✅ |
| 1 nm | 2 nm | 7.17 ✅ |

**要 `s` 落进真实 Ti64 的 3~10**，两条独立估算给出：
* 闭式 ⇒ `wgb` = **0.7 ~ 3.1 nm**
* 按 T11 实测锚定 ⇒ `wgb` = **0.15 ~ 0.68 nm**

**⇒ 合并：`int_width` 需要 0.3 ~ 6 nm。生产是 4000 nm ⇒ 差 700~27000 倍。**
**⚠ 而且 0.5 nm ≈ 2 个 β-Ti 晶胞 —— 已到原子尺度，超出连续相场自己的适用域。**

### 3.4 两笔账（都相对生产现状）

**网格这笔 —— 用户的直觉是对的** ✅

```
加密带单元数  N = 16 · L_int / d        （dx = d/4，满足项目 d/dx ≥ 4 判据）
```

`L_int` = 界面总长（晶界网络 + 固液前沿）。由 AMR 实测 +55% 单元**反推**得
`L_int ≈ 6 mm`（⚠ **这个数是反推的，值得实测确认**）。

| 界面宽 `d` | `dx` | 加密带单元数 | 相对现在 |
|---|---|---|---|
| 2 µm（现状） | 0.5 µm | 4.7e4 | 1× |
| 20 nm | 5 nm | 4.7e6 | 100× |
| **2 nm** | 0.5 nm | **4.7e7** | **1000×** |
| 1 nm | 0.25 nm | 9.4e7 | 2000× |

**⇒ "只加密晶界网络"确实把 1e12 的天文数字拉回了 1e7~1e8 这个可谈论的范围。**

**时间步这笔 —— 致命，AMR 完全碰不到** ❌

项目**自己实测过**（`VALIDATION_STATUS.md:965-983`）：

| `wGB` | 8 µm | 4 µm | 2 µm |
|---|---|---|---|
| 实测 `dtmax` | 8e-6 | 2e-6 | 0.5e-6 |

**`dtmax ∝ wGB²`** —— 界面越薄，它自己弛豫得越快，数值上必须跟住。
**这是时间上的约束，加密空间对它一点用没有。**

从 4 µm 到 2 nm：`(4000/2)² = ` **4×10⁶ 倍的时间步数**。

**合起来**：

| | 网格 | 时间步 | 总代价 | 折算（现状 ≈ 19 h/轨迹） |
|---|---|---|---|---|
| → 200 nm | 10× | 400× | 4×10³ | 3 年 |
| → 2 nm | 1000× | 4×10⁶ | **4×10⁹** | **87 万年** |

**⇒ 不可行。缺的不是 2 倍 3 倍，是 4~9 个数量级。**

### 3.5 出路（**这也是给用户论证"晶界就是瓶颈"的正确姿势**）

**别在熔池网格里缩晶界，把晶界从熔池网格里拿出来做成独立的子问题。**

| | 全域加密 | **逐面子模型** |
|---|---|---|
| 域 | 430 × 150 µm | **100 × 100 nm**（或 1D 横跨） |
| `dx` | 0.5 nm | 0.5 nm |
| 单元数 | **4.7e7** | **~4e4**（1D 只要 400） |
| 时间步 | 全局 4e6× | 只在小域、只跑短窗口 |
| **可行性** | ❌ | ✅ **分钟级** |

**⇒ 这正是 `RESEARCH_INTENT.md` §二写的架构**（算子作用于每个晶界面、
每个单元独立地传统解或 NN 解）。子模型就是那个"传统解"。

**⇒ 顺带解决三件挂着的事**：
1. **粗模型里 3 个"凑"的参数**（`D_L` 子网格闭合 1.2e-6、antitrapping `ALPHA=2`、
   `κ_c=1e-14`）全是替未解析的界面打工 —— 子模型的职责就是**把这 3 个数从物理里算出来**。
   ⇒ **极硬的验收判据：子模型必须复现 `ALPHA ≈ 2` 和那条 `D_L` 闭合。**
2. **T13 拖曳**小 1e8 —— 拖曳正比于**局域 `Δc`**，子模型里 `Δc` 是物理的 ⇒ 拖曳自然回来。
3. **`Q_GB(Δθ)` 与温度依赖** —— 子模型可以扫 `Δθ` 和 `T`。

**⚠ 论证时的坑**：不要说"我要证明现有模型里晶界很贵" —— 现有模型里晶界是个 2 µm 的模糊带，
**没有"精细仿真"**，这个论证不成立。正确的说法是：

> 晶界的真实尺度与熔池尺度相差 5 个数量级、与时间步约束差 7 个数量级（有实测标度律），
> **它在单体模型中不可达（差 4~9 个数量级）**，因此**必须**分解为子模型；
> 而子模型的算力**全部**花在晶界上。⇒ **加速晶界 = 加速全部。**

这个论证更硬，因为它是**尺度分离逼出来的**，不是设计出来的（否则审稿人会指循环论证）。

**验收**：`run_antitrap_check.sh` **22 项全过** + `--check-input` → `Syntax OK`（348 s）。

## §9 坑（本会话新增的，**`AGENTS.md` §3 那 29 条之外**）

### 9.1 工具类

| 坑 | 症状 | 做法 |
|---|---|---|
| **`--check-input` 不是秒级** | 实测 **≈120 s**（花在几条巨型 parsed 表达式的 LLVM JIT 上）。**它跑在 `executeExecutioner()` 之后**，所以一个 4 小时的长跑会**跑完全程才中止** | 该做还要做（远小于长跑），但**做时间预算**，别以为它秒回 |
| **`LineValueSampler` 每个时间步写一个 CSV** | `os.listdir(...)[0]` 拿到的是**随机时间步**，会得出"400 步上 `k_eff` 逐位不变"这种假象 | 按 `_(\d+)\.csv$` 的**数值后缀排序**取最后一个 |
| **守恒量"逐位不变"是初值钉住的**，不是稳态 | `∫(c−c0)dx` 在 407 步上逐位相同 —— 那是 Cahn–Hilliard 的守恒量，**由初值决定** | 判稳态/剖面要用**剖面自身的形状**（`L_eff`、`c_max`） |
| **`[Debug] show_material_props`** 才是权威属性清单 | 正则按 `(N) name : type` 抓会抓到 0 个（MOOSE 打的是 `Active Materials:` / `Property Names:` / `Consumed Material Properties:` 三段） | **先 `head` 看原始文本再写正则** |
| **Windows 侧 python3 没有 numpy** | `ModuleNotFoundError` | 分析脚本用**纯标准库**（如 `gb_width_vs_s.py`），或走 WSL 的 conda |
| **Windows 侧 python3 输出中文报 GBK 错** | `UnicodeEncodeError: 'gbk' codec` | 加 `PYTHONIOENCODING=utf-8` |

### 9.2 环境类

* **WSL 整个卡死**：判据是 `ps -e --no-headers | wc -l` 返回 **0**（`/proc` 都读不到）。
  `wsl --shutdown` **有时不够**，要 `wsl.exe --terminate Ubuntu` 再 `--shutdown`。
  完整分诊与抢数据流程见 `AGENTS.md` §3.12。
* **`.codex/config.toml` 的 `web_search = "disabled"`** —— 本项目有大量文献检索工作，
  需要时得显式开启。另：`[projects.'...']` 信任列表里**可能没有 `f:\speed_up`**，
  用 Codex 在本仓库工作前先加进去。
* **代理**：WSL 里用 `wsl_proxy.sh` 开（它会动态探测 Windows 主机 IP，
  NAT 模式下 `127.0.0.1` 不通，且主机 IP 每次重启会变）。

### 9.3 工作方法（**比技术坑值钱**）

1. **先确认「解的是不是同一个方程」，再谈求解器。**（D 版卡死数周的根因）
2. **隔离实验必须"只差一个因素"**，否则"哪个因素是元凶"只是运气。
3. **判据要写成「差异落在求解器容差量级内」，不是「逐字节相同」** ——
   雅可比一变，牛顿路径就变，末几位必然分叉。
4. **守恒量做差得到的后处理，先问它的噪声地板在哪。**
   能从原始剖面读的量，不要从守恒量的差去反推。
5. **探针/检查工具必须先做「正对照」** —— 拿一个"已知答案"跑通工具，再相信它对"未知答案"的报错。
6. **文档里的现成结论本身也可能是错的** —— 搜到之后还要独立判它对不对。
   （本轮 T7 就是被错的文档说服过）
7. **停后台任务 ≠ 停子进程。** `readlink /proc/<pid>/cwd` 里带 `(deleted)` 的是僵尸。
8. **别用 `pkill -f` / `pgrep -f` 杀 MOOSE** —— 命令行含该字符串的**你自己的 shell** 也会被杀
   （退出码 9）。用 `pgrep -x` + 按 cwd 限定。

## §10 最后
