## 五、步骤 4：`f_grain` 验证（完成，机器精度通过）

### 被验证的公式

从 `modules/phase_field/src/kernels/ACGrGrPoly.C:61` 反推：

```cpp
return _mu[_qp] * (op*op*op - op + 2.0 * _gamma[_qp] * op * SumOPj);   // SumOPj = Σ_{j≠i} η_j²
```

```
f_grain = mu·[ Σᵢ(ηᵢ⁴/4 − ηᵢ²/2) + (γ/2)·Σ_{i≠j} ηᵢ²ηⱼ² ]
        = mu·[ Σᵢ(ηᵢ⁴/4 − ηᵢ²/2) +  γ ·Σ_{i<j} ηᵢ²ηⱼ² ]      （因 Σ_{i≠j} = 2Σ_{i<j}）
```

交叉项系数是 **γ/2**（等价于 `Σ_{i<j}` 前系数 γ）。**已实测证明正确。**

### 验证结果

```
     eps            数值 dF/dη0        解析 ∫dfdop0 dV         相对误差     判定
   0.001  -1.107000000000e+05  -1.107000000000e+05    1.900e-13     OK
  0.0001  -1.107000000000e+05  -1.107000000000e+05    2.563e-14     OK
✅ 通过：f_grain 的梯度与 ACGrGrPoly.C:61 一致，可用于诊断。
```

**为什么是 1e-13 而不是"<1e-6 就行"**：`f_grain` 对 η₀ 是**四次**多项式，而四点中心
差分 `(F₋₂−8F₋₁+8F₊₁−F₊₂)/(12ε)` 的误差项是 `−(1/30)ε⁴f⁽⁵⁾`——对四次以下多项式
**精确**。所以两档步长给出逐位相同的 `−110700.0`，这是"机器精度一致"而非"近似吻合"。

### 判据是怎么设计的（避开了一个陷阱）

原方案是比对 `DerivativeParsedMaterial` 自动生成的导数属性（`dF_grain/dgr0`）。
**放弃了**——该属性名的拼接规则没在源码里查到确证，而"没验证过的机制不要用"是
本项目最贵的一课。

改用：把 `ACGrGrPoly.C:61` **逐字转录**成普通 `ParsedMaterial`（`dfdop_check*`），
直接比两个积分。⇒ 核对的是"**我反推的 f_grain 的梯度**"对"**MOOSE 核实际用的
表达式**"，而不是"我的公式"对"我的公式"。转录只有一行，肉眼可核。

### 过程中踩到并修掉的一个脚本 bug（值得记住）

第一版脚本 FAIL（相对误差 4.2e-3），但**公式没错**——是比错了对象：脚本拿
`eps=+1e-3` **扰动点**上求值的 `M0` 当判据，而 `M0` 本身依赖 η₀：

```
dM0/dη0 = mu·(3η₀² − 1 + 2γ(η₁²+η₂²)) = 9e5 × 0.515 = 4.635e5
⇒ eps=1e-3 时引入 4.635e2 的系统偏差 → 相对误差 4e-3（正是观测到的量级）
```

**教训**：做数值验证时，"被比较的量本身是否随扰动变化"必须先想清楚。
今后面上其它积分量的验证都要先过这一问。修法：先跑一次名义状态取判据。

### 6.5 序参量越界：诊断结论（用户 2026-09-18 指示"处理"）

> **⚠ 本节已过时。** 完整的调查（6 个变体、5 个被证伪的假设、分两层的结论）
> 已移入 **`GATE1_PLAN.md` §二**。本节保留以记录当时的推理轨迹。

#### (a) 越界是求解中长出来的，不是初值带的

源码 `PolycrystalVoronoi::computeDiffuseInterface`（`PolycrystalVoronoi.C:305-326`）
是**多个 tanh 因子的乘积**，每个因子 ≤ 1 ⇒ **初值恒 ≤ 1**。实测印证：

| | max η | min η | max Ση² | η>1 节点 |
|---|---|---|---|---|
| Exodus 帧 0（t=0） | **1.0000** | **0.0000** | **1.0000** | **0** |
| 帧 1（t=3.875e-7，档 A） | 1.4960 | −0.0673 | 2.2379 | 421 |

#### (b) 解析解证明：Ση² > 1 一定是数值伪影，不是物理

`f/mu = Σ(η⁴/4 − η²/2) + γ·Σ_{i<j}ηᵢ²ηⱼ²`，γ=1.5。求各情形的均匀平衡：

| 情形 | 解 | Ση² |
|---|---|---|
| 晶粒内部（单个 η） | η = 1 | **1.000** |
| 单晶界中点（两个相等） | η₁=η₂ = 0.5000 | **0.500** |
| 三叉晶界（三个相等） | η = 0.37796 | **0.4286** |

⇒ **平衡态 Ση² ∈ [0.5, 1.0]，绝不超过 1**。实测最大 1.14 ⇒ **数值伪影**。

#### ⚠⚠ (c) 更正（2026-09-18 晚）：真正的根因**不是**界面欠解析

下面 (c) 的"根因是界面欠解析"是**当初的诊断，现已被 smoke test 证伪**。
保留原文以记录推理过程，但**结论以下面这段为准**。

**证伪实验**：把 `wGB` 从 4 µm 加到 12 µm（单元/界面 1.41 → 4.24，满足判据），
同输入、同 `end_time`、只差 wGB，两个单进程并发：

⇒ 分辨率提高 3 倍，越界**几乎没变**（差 0.4%）。**"欠解析"不是根因。**

**真正的根因：初值与液相不自洽。**

t=0 的场（Exodus 帧 0）实测：

```
液相内（T>1903，5246 个节点）:  max(η) = 1.000000    Ση² 最大 = 1.0
  其中 Ση²>0.5 的节点: 499 个 (9.51%)
  这 499 个节点的 T−1903:  min=0.2  中位=49.6  max=203.3 K   ← 全在"刚刚熔化"的浅层
  整个液相的   T−1903:  中位=861.8  max=13197 K              ← 熔池深处热得多
```

机制：
1. `PolycrystalColoringIC` 只作用于 `block = 0`（固相），但**边界上共享的节点**
   把 Voronoi 的 η=1 带进了液相 ⇒ 熔池边界出现**一个单元宽的 η 阶跃**。
2. 该处 T≈1903 ⇒ **μ ≈ −0.5μ₀**（μ 过零在 **T = 1882.2 K**，即 `tanh = −1/3`），
   势阱几乎压平 ⇒ 把 η 拉回 1 的回复力趋近于零。
3. 阶跃产生的巨大 ∇²η 把 η 推过 1 ⇒ 越界集中在熔池边界
   （实测最严重的 5 个节点全在 x≈−1.0~−1.06e-4、T=1817~1878 K）。

**⇒ 这是初值问题，不是离散化问题。** 阶跃是初值给的，网格加密不会消掉它。

**可能的修法（未实施，属模型改动，需验证）**：让初值在熔池边界按界面宽度 `w`
**平滑过渡**，而不是按 block 硬切。但这会直接撞上尺度矛盾——
真实 LPBF 的固液界面只有 nm 级，相场的弥散界面是 µm 级，
**这正是专家评审里点过的 `W/(D/V)` 尺度问题，属 Gate 1 范围**。

### 9.1 ⚠ 全尺寸跑死了四次 —— **根因是我自己，已修**

| 次 | 时长 | 结果 | 退出码 |

#### ⚠⚠ 更正：不是"外部 SIGKILL"，是 `run_nonad_prod.sh` 自己的清理代码

原结论写的是"原因未定"，**那是错的**。真因在 `run_nonad_prod.sh:36-37`：

```bash
pgrep -f 'phase_field-opt -i' > /tmp/mp.txt 2>/dev/null
xargs -r kill -9 < /tmp/mp.txt 2>/dev/null
```

它只按**命令行字符串**匹配，**无条件杀掉整台机器上的每一个 MOOSE 进程**，不管是不是
本目录的。而我为了测试这个脚本，反复用 `head -N` 截断后运行它 —— 截断版**仍然包含这段
preamble**，于是**每一次测试都把自己的长跑杀掉了**。四次 SIGKILL 全部由此而来。

排查时被排除的那些原因（**结论仍然成立，只是没找到真凶**）：
不是 OOM（24 GB 只用 3.5 GB）、不是 WSL 重启（`uptime` 连续）、不是我的 `pkill`。

**教训（比 checkpoint 更值得记）**：
1. 一个脚本的"清理"动作如果**不限定作用域**，它就是一个常驻的破坏源。
2. 测试脚本时用 `head -N` 截断**并不会**去掉开头的副作用代码 —— 截断只能去掉尾部。
3. "排除法"排除了三个假设之后，应该继续查**自己执行过的每一条命令**，
   而不是跳到"外部原因、原因未定"。

#### 修法

只清 **cwd 等于 `$D`** 的残留进程，并打印被杀的 PID 与目录，让"谁杀了谁"永远可见：

```bash
for P in $(pgrep -x phase_field-opt); do
  CWD=$(readlink /proc/$P/cwd 2>/dev/null | sed 's/ (deleted)$//')
  [ "$CWD" = "$D" ] && { echo "  停掉本目录（$D）的残留进程 pid=$P"; kill -9 "$P"; }
done
```

**实测验证**：先起两个对照算例（pid 13517 / 13519），再运行截断版生产脚本 ——
运行前后都是同样的 2 个 PID，输出 `已停本目录残留进程 0 个；机器上仍有 2 个 MOOSE 在跑（不属于本目录，未动）`。

#### 仍然要做的那件事（checkpoint）

即使真因已修，**续跑能力本身仍然必要**（机器可能真的崩）。见 §11.2。
所以 checkpoint 的修改**保留**，理由从"防外部 SIGKILL"改成"通用的长跑韧性"。

`wGB` 在生成器里是**单参数控制**，三处同步流动：

```
mu0 = 6σ/wGB        (barrier_mu, 在 c.i 里 —— splice 不碰它)
κ   = a*·wGB·σ      (kappa_aniso)
L   = 4/3·M0/wGB    (L_aniso)
```

**为什么这是自洽的改动而不是随手调参**：

```
κ·μ0 = (a*·wGB·σ)·(6σ/wGB) = 6·a*·σ²     ← wGB 精确抵消
```

⇒ Moelans 不动点 `(a*, gamma*)` **与 wGB 无关**，只有 κ 随 wGB 线性缩放；
σ 与一维界面速度（`v = L·Δf`，`L ∝ 1/wGB`）都不变。这是经典薄界面结果。

**改动**：`frozen/gen_aniso_nonad.py` 增加 `--wgb`（默认 `4.0e-6`）。
**默认产出已两次验证与改动前逐位相同**（`stage1_meltpool_d.i` 的 sha256 均为
`2c10a73b…`），所以冻结所保护的"可复现性"未被破坏。已重新登记哈希并写明理由。

**对照实验**（正在跑）：同输入、同 `end_time=1e-6`、只差 wGB，两个单进程并发。

| 算例 | wGB | κ | μ0 | w | 单元/界面 |
|---|---|---|---|---|---|
| `cmp_base` | 4 µm | 1.8e-6 | 9.0e5 | 1.414 µm | **1.41**（欠解析） |
| `wgb12` | 12 µm | 5.4e-6 | 3.0e5 | 4.243 µm | **4.24**（达标） |

判据：序参量越界（基线为 max η 1.02~1.07、Ση² 最大 1.14）。

**⚠ 代价**：界面变厚。柱状晶宽约 40 µm，w=4.24 µm 占 10%，尚可；
但更小晶粒与三叉晶界行为会受影响。**这是"用界面厚度换分辨率"的取舍，不是免费的。**

### 11.4 `Mesh/nx` 陷阱（#4）：预检运行器

`run_checked.sh`：先用 `--mesh-only` 跑**完全相同的 CLI 覆盖**（几秒到几十秒），
它会做完输入解析因而触发"未使用参数"检查；**通过了才跑真算例**。

**实测**：
```
反例  bash run_checked.sh N.i Mesh/nx=86 Executioner/end_time=1e-7
      → ❌ 预检失败，真算例根本没启动（退出码 1）
正例  bash run_checked.sh N.i Mesh/gen/nx=86 Mesh/gen/ny=30 ...
      → ✅ 预检通过（Elems = 2580），真算例跑完 18.16 s
```

> Gate 1 的参数扫描全是 CLI 覆盖，这个工具正好用得上。

### 11.5 顺带修掉的一个**我自己工具里的** bug（实验暴露的）

`gate0_report.py` 与 `run_nonad_prod.sh` 原本都读生成的 `.i` 文件头那行
`# [consts] kappa_op=1.8e-6, gamma_asymm=1.5` 来算界面分辨率。
但那是**静态模板文本**（描述 C 版基线），**不随 `--wgb` 变化** ——
跑 wGB 变体会拿 `1.8e-6` 配 `mu0=3.0e5`，算出错误的 w。

**修法**：生成器在 `aniso_block.i` 头里输出一行机器可读的实参
```
# GENERATED_PARAMS wgb=1.2e-05 kappa_op_iso=5.399829064e-06 gamma_asymm_iso=1.499918283 mu0=300000
```
工具**跨目录内所有 `.i` 文件**收集它（因为 `splice` 会重写 `d.i` 的文件头，
最终输入里没有这一行），并加了一道**硬校验**：
生成器的 `MU_QP` 必须逐位等于算例 `[barrier_mu]` 的 `mu0`，不等就拒绝运行
—— 这正是"改了 `--wgb` 却忘了改 `barrier_mu`"会踩的坑。

实测：变体算出 `w=4.243 µm, 4.24 单元/界面, mu0_consistent=True`；
默认配置仍是 `1.41 单元/界面, ok=False`。
