## 一、项目目标（用户明确表述）

加速面向 **Ti-6Al-4V 的 LPBF 增材制造**中的**耦合「晶粒结构演化 + 元素扩散」**计算。

手段：用 **MOOSE 相场仿真**为**神经算子**生成训练数据。

---

## 二、要学的是什么（用户明确表述）

> 「我的目标**不是**去学习晶粒的演化。」
>
> 「晶粒的拓扑演化我认为**并不是耗时最长的计算开销**，并且**神经算子并不好学到拓扑变化**，
> 溶质与元素的转移与分配应该更多一些。」
>
> 「我的算子是**作用在每一个晶界上**，学习**晶界上的元素与溶质的扩散**，
> 而晶粒的拓扑演化使用传统方式进行计算。」

**要点：**

| # | 要点 |
|---|---|
| 1 | 算子的**作用对象是每一条晶界（面）**，不是整场 |
| 2 | 算子**学习的内容是晶界上的元素/溶质扩散与分配** |
| 3 | **拓扑演化不是主要学习目标** |
| 4 | 理由之一：神经算子**不好学拓扑变化** |

## 三、核心架构：两条轨道 × 两个阶段（用户明确确认）

### 3.1 两条轨道

> 「我认为应该将**拓扑变化**与**晶界上溶质的变化分离开来，拆成两条轨道**。」

```
拓扑轨道 T:   T_n ──[传统相场 或 神经网络]──▶ T_{n+1}
溶质轨道 C:   C_n ──[神经网络(逐面算子) 或 传统求解器]──▶ C_{n+1}
```

### 3.2 耦合方式：离散、交错

> 「**离散开来看**就是上一步的拓扑变化得到的结果影响这一步溶质的变化，
> 这一步晶界上溶质的变化会影响下一步的拓扑变化。」

```
上一步的拓扑结果  ──▶ 影响这一步的溶质变化     C_{n+1} = F_C(T_{n+1}, C_n)
这一步的溶质变化  ──▶ 影响下一步的拓扑变化     T_{n+2} = F_T(T_{n+1}, C_{n+1})
```

**两个轨道相互给到其下一步演化需要的数据。**

### 3.3 两条轨道贯穿两个阶段

> 「两条轨道**贯穿两个阶段**。」

⇒ 2（轨道）× 2（阶段）= **2×2**：

| | **阶段 1**：熔化 → 凝固 | **阶段 2**：凝固后粗化与偏析 |
|---|---|---|
| **拓扑轨道** | 形核 + 外延生长 + 竞争生长 | 粗化（晶粒长大/消失） |
| **溶质轨道** | 凝固前沿的偏析 | 晶界偏析与扩散 |

> 用户对两个阶段的表述：
> - 算子 1：「阶段一熔化到凝固的算子，这里涉及到**晶粒的形核与生长**等等」
> - 算子 2：「凝固后**粗化与偏析**阶段的算子，这里主要就是凝固后的发展」

### 3.4 每格可自由选择求解方式（用户明确表述）

> 「拆开之后**可以用传统求解器计算拓扑变化，也可以训练神经网络来计算拓扑变化**。」
>
> 「拓扑变化**并不是不能进行机器学习**。」

⇒ **2×2 的每一个格子都可以独立选择「传统求解器」或「神经网络」。**

【推导】拆分的收益（未经用户确认，仅供理解）：
1. **可替换性** — 贵的用 NN，需要精度的用传统求解器
2. **可学习性** — 拓扑之前难学是因为与溶质耦在一起、输入输出不干净；
   拆开后变成「晶粒网络 → 新晶粒网络」，输入输出明确，**可以训练**
3. **误差隔离** — 尺度分离问题只存在于溶质轨道
4. **可归因** — 两条轨道可分别验证

## 四、物理真实性要求（用户明确表述）

> 「并且我需要**学习接近真实的物理，尽量将仿真往真实的物理层面靠拢**。」
>
> 「**真实溶质对拓扑的反馈是怎样的就怎样反馈**。」

**这两条是硬要求，含义：**

| # | 含义 |
|---|---|
| 1 | 算子要学的是**真实物理**，**不是**复现 MOOSE 这个粗模型（不是纯 surrogate） |
| 2 | **溶质 → 拓扑的反馈必须按真实物理实现**，不能省 |
| 3 | ⇒ 任何"模型本身的物理局限"都是**真缺口，必须解决**，不能用"如实声明"绕过 |

**对已知缺口的直接影响：**
- **C4（溶质截留/尺度分离）**：必须修。模型当前把溶质的动力学放慢了约 10⁶ 倍，
  微观偏析**幅度错约 3 倍、空间尺度错约 1000 倍**（详见 ROADMAP §4.3）
- **C8（溶质→拓扑反馈）**：当前**完全没有**（`f_loc` 只进 c 方程，不进 η 方程），
  必须按真实物理补上（详见 ROADMAP §0.4）

## 五、优先级（用户明确表述）

> 「我认为**首要工作是用来最快速度证明仿真的正确性与收敛性，生产先不启动**。」

> 「先使用非 AD，然后解决完所有的物理缺口，开始推进。」

**⇒ 顺序：正确性与收敛性 → 补完物理缺口 → 才启动生产（数据生成）**

**另一条硬约束**：
> 「保证在**不崩溃**的同时最大化利用电脑性能。」

## 六、由本思路直接导出的、不可违反的推论

以下是我从上述意图**推导**出的约束（标注 `【推导】`），可用于自查是否跑偏：

| # | 推论 | 依据 |
|---|---|---|
| 1 | **数据生成必须放在阶段 C 全部完成之后** | 任何物理改动（`k`、`A_ani`、形核、截留、反馈）都会让此前数据作废；且 `feat_spec.py` 的特征 7/11（`c_bulk`）是绝对量，随 `c0` 变尺度 |
| 2 | **溶质轨道的物理保真度是项目的核心指标** | 用户明说"算子是学晶界上的溶质扩散"+"要接近真实物理" |
| 3 | **拓扑轨道的实现方式是可选项，但接口必须干净** | 用户明说"可以用传统求解器，也可以训练 NN"⇒ 两条轨道必须能互换而不影响对方 |
| 4 | **不能把"模型局限"当作可接受的终点** | 用户明说"尽量往真实物理靠拢" |
| 5 | **算子必须是"逐面/逐晶界"的** | 用户明说"作用在每一个晶界上"；现有 `feat_spec.py` 的 26 维特征已是面级的，方向一致 |
