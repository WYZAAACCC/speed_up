## §1 现求解器的**输入与输出**（逐行核实 `windowB_surface.py`）

### 1.1 定义与入口
| 项 | 位置 |
|---|---|
| `def elastic_driving(self, soft=None)` | **`:4043`** |
| `def elastic_driving_pair(self, karr, larr)` | **`:4265`** |
| 求解核心 `PF3D`（FFT 谱法） | `windowB_pf3d.py`（构造于 `windowB_surface.py:1369`） |

### 1.2 ★ 输入（三条）
| # | 输入 | 来源 | 说明 |
|---|---|---|---|
| **①** | **`ε⁰` 场**（每个变体的本征应变） | `eps0`（构造参数）与 `pf.eps0_fields()` | **6 分量对称张量** |
| **②** | **指示场 `h`**（各变体的体积分数） | **`soft=True` ⇒ 由 `_soft_h_at` 现算**（`:4187`）；`soft=False` ⇒ 硬 `region` | ⚠ **`soft=True` 即"把 `ε⁰` 抹宽 1.5 胞"** |
| **③** | **弹性刚度 `C`** | `C_hex_tab` / `C_cub` 或单一 `C` | 各相各向异性 |

**⚠ 关键**：**现求解器**不需要**"界面位置/法向"作为显式输入** ——
它是**通过 `h` 场（弥散或硬指示）间接知道界面的**。
**⇒ 这正是"锐界面求解器"要改的地方**：它需要**显式的界面几何**（位置 + 法向）。

### 1.3 输出（两条）
| # | 输出 | 形状 | 说明 |
|---|---|---|---|
| **①** | **`ed`**（弹性驱动力） | `(nreg, N, N, N)` | **只有它被下游消费** |
| **②** | `σ`（应力张量） | — | ⚠ **`windowB_surface.py:2780` 明记："引擎**没有** `σ` 张量这个量"**<br>⇒ **只有 `PF3D.sigma_tensor()` 内部临时算** |

**⇒ ⚠ 这是一个重要的接口事实**：
**引擎对外只暴露 `ed`，不暴露 `σ`** ⇒
**D3 的 `J2`（面力连续 `[σ·n]=0`）与 `J7`（力平衡 `∇·σ=0`）**
**需要**新增**"输出 `σ`"的接口**，否则判据无法直接测。

## §3 ④ 新开关（默认关）+ 回归方案

### 3.1 开关设计（建议）
```
--el-sharp 0|1        # 0 = 现状（FFT + soft 涂抹）；1 = 锐界面求解器
```
**⚠ 必须默认 `0`** ⇒ 关闭时**逐位不变**（`R629 E1` 的硬要求）。

### 3.2 回归方案（**照抄仓库既有做法**）
| 步 | 做法 | 依据 |
|---|---|---|
| 1 | `bash _r30_regress.sh` ⇒ **共有列差异 = 0** | `R629 E1` / `BLOCK_SELFAC` W-4 |
| 2 | **计数回归**（`el.sigma_tensor` / `el.eps0_fields` / `argmin2` == 1.00/步） | `P2`（"回归全绿 ≠ 没有性能回归"） |
| 3 | **宿主指纹先打** | `P1`（`_r576_hostfp.py`） |
| 4 | **真实路径冒烟**（不只单元量具） | `P3`（"单元量具过 ≠ 真实路径过"） |

### 3.3 ⚠ 与 `soft` 的关系（**必须显式处理**）
现 `soft=True` 是**默认**（`windowB_surface.py:1253`）
⇒ **新开关与 `soft` 是两个正交的量** ⇒ **建议**：
* `--el-sharp 1` 时 **`soft` 应被忽略**（锐界面不需要涂抹）⇒ **但要显式记账**（不能静默）；
* **`--el-sharp 0` 时 `soft` 行为完全不变** ⇒ 保证回归。

## §4 ★ 本步发现的**三个接口障碍**（必须先解决才能实施）

| # | 障碍 | 后果 |
|---|---|---|
| **①** | **引擎不暴露 `σ`**（`:2780` 明记） | **D3 的 `J2`/`J7`（面力连续、力平衡）无法直接测** ⇒ 必须**新增 `σ` 输出** |
| **②** | **现求解器不接收"界面几何"**（只收 `h` 场） | 锐界面求解器**需要新的输入接口**（界面位置 + 法向） |
| **③** | **FFT 谱法要求周期性 + 规则网格** | 锐界面的**离散化方式**必须与该约束兼容（这正是 D1 的五类方案要比较的核心） |

**⇒ 障碍 ③ 把 D4 与 D1 绑在一起**：
**`D4` 的接口设计取决于 `D1` 选哪一类方法** ⇒ **D1 必须先做完。**
