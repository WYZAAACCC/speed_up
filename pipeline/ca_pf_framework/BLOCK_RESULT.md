## 1. 结论

**目标**：块 = 多根同类板条堆叠 + 低角晶界分隔，**多个板条核能生长并且堆叠**
形成一个**完整且物理正确**的块。

**结论一（截至 Round 26，归档配置 `eng12`）**：
> **在给定的形核节奏下，6 根同变体板条由 5 次邻位形核逐个长出并堆叠，
> 每一对相邻板条之间是一张干（无 β 夹层）的低角晶界；
> 末态 6 片全在位、无缺片、无显著碎裂；界面在两次形核之间不迁移。
> 上述结论由引擎自己的放置规则产生，且在 3 个随机种子上均成立。**

**结论二（R29，闭环配置）**：
> **「块里几根板条」不再是规定值，而是导出量**：
> `n = floor(α_KM·(M_s − T_end))`，逐根形核温度 `T_k = M_s − k/α_KM`。
> 用 `α_KM = 1.1e-2 /K` 得 `n = 6`（与归档"规定的 6"**独立地一致**），
> 逐根温度与**步数**都被实测逐点命中（差 0.1–0.2 K / 1 步）；
> 换成 `α_KM = 5e-3` ⇒ `n = 2`，`T_2` 从 691 K 变 473 K，闭式**仍然命中**。
>
> ⚠ **但必须一起报**：① `α_KM` 仍是 [标]（可测，尚无 Ti-64 实测值）；
> ② 闭环配置的 **`V-8b`（末态厚度保真）实测 FAIL** —— 原因是
> **"共享界面咬掉的量"不是常数**（见 §4 限制 8 与 `BLOCK_STATUS §28.11`）。

**结论三（R29，"几何 vs 形核供给，谁限速"）**：
> **供给限速，不是几何限速。** 两条上限：**供给** `n_kin = α_KM(M_s − T_f) = 6.3`；
> **几何** `n_geo_cap = 21`（AABB 精确判据）⇒ `n = min = 6`，**供给更小 ⇒ 供给限速**。
> "几何开始咬人"的温度 `T_bind = M_s − n_geo_cap/α_KM = **−1036 K**`（不物理）
> ⇒ **几何永远不咬人**，即便板条面内长到种子的 1.8 倍（`n_cap` 21→15）也仍是供给限速。
> ★ **负对照**：缩回归档几何（`Δx=62.5 nm`）并取 `t=0.68 µm` ⇒ `n_cap = 3 < 6`
> ⇒ **变成几何限速** —— 这说明**归档配置其实一直是几何受限的**（一个此前没被指认的隐性缺陷，
> 也正是 C-4 逼着把 `Δx` 放大到 125 nm 的原因）。
>
> ⇒ **可证伪的推论**：`n` 与 `T_end` **成线性**（斜率 `−α_KM`）⇒
> **冷得越深、板条越多、块越厚**（`W_block = n·t`）。**这是工艺可调的** ——
> 同一台机器上改冷却终温，数块里几根板条。（C-8，自检 6 条对照）

## 3. 推荐配置（可复现的完整命令行）

```bash
cd pipeline/ca_pf_framework
export MALLOC_MMAP_THRESHOLD_=65536 MALLOC_TRIM_THRESHOLD_=65536 MALLOC_ARENA_MAX=2
python -u _bk_exp.py --arm eng \
  --N 96 --dx-nm 62.5 --steps 200 --every 10 --snap-every 50 --pair-every 10 \
  --norm-smooth 0 --nthreads 2 --reinit-dt 1e-4 \
  --grow-stack --nuc-every 0 \
  --eng-cadence 30 --eng-elong 3.75 \
  --eng-t-nm 312.5 --eng-t-last-reduce-nm 31.25 \
  --nuc-overlap-nm 62.5 --eng-seed 11 \
  --tag eng12 --out _exp/_bk_eng
```

**判定**：`python3 _bk_verdict.py --root _exp/_bk_eng --tag eng12 --arms eng --ctrl-tag L200`
**稳健性**：`python3 _bk_rscores.py eng12 eng13 eng14`

### 3.1 ★ R28 起：**默认路径就是引擎**（更短，且逐位等价）

```bash
python -u _bk_exp.py --N 96 --dx-nm 62.5 --steps 200 --every 10 --snap-every 50 \
  --pair-every 10 --norm-smooth 0 --nthreads 2 --reinit-dt 1e-4 \
  --grow-stack --eng-cadence 30 --nuc-overlap-nm 62.5 \
  --tag def1 --out _exp/_bk_eng
```

**核验**：`python3 _bk_defcheck.py` ⇒ 与 `eng12` 的 `series.csv`
**逐位比较（忽略 `wall_s`）差异字段数 = 0**。

机制：`--nuc-mode`（默认 `auto`）—— **`--grow-stack` 且 `--nuc-every ≤ 0` ⇒ 引擎**；
给了 `--nuc-every > 0` ⇒ 驱动层。**归档命令行全部显式传了 `--nuc-every 30`
⇒ 它们的行为逐位不变**（`--nuc-every` 的默认已从 30 改为 **0**）。
引擎路径下**自动**取 `elong = plate_L/plate_W`、`t = 250 + o`、`t_last = t − o/2`。

**六个参数的物理含义**（缺一不可，每一个都有实测依据）：

| 参数 | 值 | 作用 / 依据 |
|---|---|---|
| `--arm eng` | — | 形核交给引擎的 `nucleate()`（`stack` 通道） |
| `--eng-elong 3.75` | 2400/640 | 核是**长条板条**而非圆盘；圆盘会让 F3 面积小 **7 倍**（§12.4） |
| `--nuc-overlap-nm 62.5` | 1Δx | 新核与旧片**共用一张界面**；0（相切）会因阶梯错位留 1 胞 β 膜（§7） |
| `--eng-t-nm 312.5` | T+o | 补厚度：界面落在重叠区中面 ⇒ 每片被吃 o/2（§8） |
| `--eng-t-last-reduce-nm 31.25` | o/2 | 末片只被吃一侧 ⇒ 对齐驱动层 `T+o/2`（§24.3） |
| `--eng-cadence 30` | — | **形核节奏（驱动层规定）** —— 见 §4 限制 1 |
| （引擎内自动） | — | `nfsv` 同变体开新场、`attach` 共用界面、`prefer_end` 端片优先、`nfsv_strict` 空场用完即拒绝、`align_inplane` 面内对齐、**自动关掉事件后的强制 reinit** |

## 4. 必须随结论一起报的限制（**不得省略**）

1. **速率仍是"给定"的** —— 但 **R29 起它已经由物理量给出，不再是自由参数**。
   两条路径并存：
   * **默认（`cadence`）**：`--eng-cadence 30` 规定节奏（本文全部读数是这条）；
   * **闭环（`--nuc-law athermal`）**：`n(T) = α_KM·(M_s − T)` 的位置饱和律
     ⇒ 板条数 `n = floor(α_KM·(M_s−T_end)) = 6` 与逐根形核温度
     `T_k = M_s − k/α_KM` 都是**导出量**（见 `BLOCK_PARAM_CLOSURE.md` C-2/C-3）。
   ⚠ **仍未标定的只剩一个常数 `α_KM`**（[标]，可测：原位 `f(T)`）。
   ⚠ 已有的 `f_nuc^crit = 4γ/d` 判据**在这两条路径上都限制不了速率** ——
   而且这**不是漏接线**：`df/fcrit ≈ 73–583`，判据被满足得远远超出门槛
   （R29 的 C-7 把它归因到 `ΔG_v ≫ 4γ/t`，是**结构性惰性**）。
   ⛔ **本条在 R29 之前的措辞是"需要一个形核速率模型（位点密度 + 自催化动力学），
      超出当前范围"—— 那句话已作废**（`--nuc-law athermal` 就是那个模型）。
2. **`_bk_exp` 的默认路径已是引擎**（R28 起）：`--grow-stack` 且未给 `--nuc-every`
   即走引擎，与显式推荐配置**逐位一致**（`_bk_defcheck.py`）。
   要复现归档的**驱动层**行为，显式传 `--nuc-every 30`（各臂 `meta.json` 的 `exp_args` 里都有）。
3. **逐板条体积波动 6–35%**（两臂共有，端片 −6.7% 完全相同）——
   成因是**内层板条两张宽面都是 F3、`Δf = Δe_el ≡ 0` ⇒ 没有体驱动力**（§5.1），
   体积只受 F3 面积最小化支配 ⇒ **是模型的性质，不是缺陷**，但必须一起报。
4. **`norm_smooth`（`∇d` 的盒滤波宽度）是离散正则化，不是物理**；生产用 `m=0`。
5. **"块内板条数"与"变体分组"在默认路径下是规定的**（G-7）；
   **取向差 θ 是输入**（G-4）；**层间的力学容纳（G-2）与 `κ_ψ>0`（G-3）未做**。
   ⚠ **R29 更新**：板条数在 `--nuc-law athermal` 路径下**已是导出量**
   （`n = floor(α_KM(M_s−T_end))`，见 `BLOCK_PARAM_CLOSURE.md` C-2），
   但**默认路径仍然规定它**；**变体分组、θ 两项未变**。
   **参数闭环全表（46 条，含 tier/出处）见 `BLOCK_PARAM_TABLE.md`。**
6. **`use_fcrit` 在本工况下两条通道上都是惰性的**（`df ≫ fcrit`）——
   引擎注释写"已接线"在机械意义没错，但**不得**被读成"形核已受驱动力判据约束"。
   ⚠ **R29 更新**：这**不是漏接线**，是**结构性惰性** ——
   `ΔG_v/(4γ/t) = 57.5`（见 `BLOCK_PARAM_CLOSURE.md` C-7）。
7. **"咬 1 胞"是模型选择**，有文献锚（Furuhara 2008 的 repeated nucleation
   adjacent to each other），**但不是从自由能推出来的**。
   （引擎里"留一层残余母相"那条是 Chen 1979 的 **Fe-Ni** 观测；
   本体系 Ti-64 的 C-1 判据给**不润湿 ⇒ 干晶界**。两条都对，对不同体系。）
8. ★★ **R29 新增（唯一一条被判 FAIL 的实质物理判据）：**
   **"共享界面咬掉的量"不是常数** ⇒ 闭环配置的 `V-8b`（末态厚度保真）**FAIL**。
   实测（`dry_cln2`，`n=2`，一张界面）：种子片播种 635 nm → 末态 **670.7 nm**
   （**根本没被咬**）；而**不补偿**的 `dry_cl1`（`n=6`，两张界面）种子片只有
   **391.8 nm**（**−23%**）。
   ⇒ `t_seed = t_phys + 被咬量` 这个**形式**对，但**"被咬量"没闭合**
   ⇒ `t_seed` 必须读作 **[标]**，不是 [推]。开关 `--seed-comp-frac` 供扫描。
9. ★ **R29 新增**：**"块内板条的面内尺寸"在本模型里不是文献值，而是生长出来的。**
   只有**惯习法向**被 `β_h` 钉住，面内 α′/β 界面继续往母相里长
   ⇒ 实测 `Vt` 是种子几何的 **1.66 倍**（面内面积 ≈ 种子足迹的 1.37 倍）。
   `L_lath = 4.59 µm`（Wang 2026 的 9:1）只是**种子**尺寸，不是末态尺寸。
10. ★★ **R29 新增（长跑才暴露出来的一条）：闭环配置在 2853 步的尺度上 `V-3g`
    （两次形核之间界面不迁移）FAIL** —— 实测 max **0.416 Δx**（门槛 0.12），
    归档 `eng12`（**只有 200 步**）是 0.0377 Δx；逐对接触面积从 `1-2=5.29` 漂到 `3.81`，
    而归档的逐对面积**平到 ±3%**。
    **根因（同一轮里我错了两次，第三版才有数据支撑）：`V-3g` 测的 `f3_pos`
    是"所有 F3 胞的 `n*` 平均位置"—— 一个汇总量。各对界面面积不等且在变时
    （`cl1b` 的权重变了 ~30%），平均位置就会挪，而 `eng12` 的各对面积齐平（±3%）
    所以它的平均位置稳。⇒ 这是**判据被混淆**，不是"界面在迁移"。**
    独立佐证：逐对界面**粗糙度**在两套配置里都是 **~0.07–0.13 × t 且不随时间增长**
    （`_bk_f3flat.py` 逐对量；`eng12`: 0.073 t，`cl1b`: 0.071 t）。
    ⚠ **建议的修法（本轮未做）**：把 `V-3g` 改成**逐对**判据。
    ⚠ 三处口径修正的账（同一轮内）：① 我先把**接触面积**的稳定当成了**界面**稳定；
    ② 再用**汇总的** `f3_std_n` 得出"归档粗糙 3.5 倍"（那个量被"界面之间的间距"主导）；
    ③ 直到**逐对**量才看清。**教训：凡是"把一群界面汇成一个数"的量
    （`f3_pos`、`f3_std_n`），先问它是不是主要在反映"有几张界面"。**

## 6. 方法学：三轮「差异是假的」与本项目最贵的一课

**对**"引擎 vs 驱动层"的任何差异下结论之前，**先用同一把尺量一遍驱动层**。
实测三例：

| 轮 | 怀疑 | 补对照后 |
|---|---|---|
| R19→20 | "面积涨到 2.2 / 拓扑非链"是我判据测错了量？ | **不是** —— 驱动层稳在 1.50–1.63 ⇒ 判据成立 |
| R24 | "`V-8b` 厚度 332 是物理偏差？" | **不是** —— 剔孤儿后 325，是**读数口径** |
| R25 | "`V-2g` 跌幅 19–35% 是引擎缺陷？" | **不是** —— 驱动层同样 6–28% |

**并且：写判据时就要用不会被离散噪声污染的读数**（"数个数"这类量尤其危险）——
同一类口径错误出现过**四次**（V-2 基准、V-6 基准、V-8b、R-5）；
另有**两次**是"读数被 1–2 体素孤立碎点污染"（`gs2` 的场 1 被拉成 868 nm）。

**⇒ 一句话**：**结论先问"我怎么证伪它"，判据先问"这把尺会不会骗我"。**
