## §3 ⚠ 现在跑仿真会怎样（**必须先知道**）

`_bk_exp.py:4825`：
```python
ap.add_argument('--out', default='_exp/_bk_block')
```
**这是相对路径** ⇒ 在 `ca_pf_framework/` 里跑且**不传 `--out`** 时，
输出会写进**刚恢复的那个小 `_exp/`**（只有 383 个文件）⇒ **不报错，但会把新运行混进证据目录**。

### 3.1 ⇒ 规则（**以后跑任何仿真都必须遵守**）
```bash
# ✅ 正确：显式 --out，且指到工作树外（或指到 winb_core 里）
python3 _bk_exp.py --out /mnt/f/speed_up_archive/_run --tag mytag ...

# ⛔ 错误：不传 --out ⇒ 写到 _exp/_bk_block ⇒ 混进证据目录
python3 _bk_exp.py --tag mytag ...
```
★ 本会话此前**所有**实验都显式传了 `--out`（`_exp/_ndirlsq`、`_exp/_t2big`、`_exp/_f2ab`…），
所以**历史结论不受影响**。

### 3.2 ✅ 已核实：不会有代码因"找不到 `_exp/`"而崩
* 闭包内**唯一**的 `_exp` 字面量就是上面那条 `--out` 默认值；
* `windowB_lath.py` / `windowB_par.py`：**0 处**；
* `_bk_measure.py:36` 的 `_exp/...` 在 **docstring** 里（示例用法，非代码）。

## §4 ⚠ 这次移动**丢了什么**（诚实记账）

移到归档里的是 **9,296 个文件 / 33.2 GB**，其中**绝大部分是 `.npz` 快照**。
**⇒ 依赖快照的分析脚本现在会找不到文件**，包括：

| 脚本 | 依赖 |
|---|---|
| `_r734_chain.py`（`f_tip` 机理） | `_exp/_bk_block/dry_B2P_q0` 的 `snap_*.npz` |
| `_r737_read.py` / `_r737_robust.py` | `_exp/_ndirlsq200/` 的 `snap_*.npz` |
| `_r738_read.py` | `_exp/_ndirlsq_seed/` |
| `_r719_s3_gauge.py`、`_r720_*.py` | 各臂 `snap_*.npz` |
| `_bk_measure.py --npz` | 任意 `snap_*.npz` |

★ **但报告引用的"表"（`series.csv` / `meta.json` / `nuc_dbg.json`）仍在原位**
（`_bk_t5/` 那 367 个）⇒ `R725`/`R740`/`R742` 里读 `series.csv` 的分析**仍可复跑**。
**⇒ 受影响的是"需要读 3D 场快照"的分析，不是"读 CSV 表"的分析。**

### 4.1 恢复办法（把某个臂的快照取回来）
```bash
# 取回单个臂
mkdir -p _exp/_ndirlsq200
cp -r /mnt/f/speed_up_archive/_exp/_ndirlsq200/dry_S_on \
      _exp/_ndirlsq200/
# 取回整个子目录（按需，别一次全取，那会把 33 GB 又搬回来）
cp -r /mnt/f/speed_up_archive/_exp/_bk_block _exp/
```
