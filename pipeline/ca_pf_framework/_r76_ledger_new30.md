## §123 R76 ★★★ **框架补全（R164）**：F2 面能的**配对依赖**已实现（默认关）+ 受控对照已启动

### 一、补的是什么（`§122` 定位的缺口）

`windowB_lath.py:23-25` 自己写着：**F1/F2 的 γ 不动**（退回标量 `gamma0`）
⇒ **V1/V3 界面的能量与 V1/V5 界面一模一样** ⇒ 生长通道**无从选择**
⇒ 这正是 `§112` 测到的「生长竞争通道没有自协调机制」的**代码原因**。

### 二、补法的物理依据（**由模型自身的量导出**，不是外来参数）

界面的**共格性**由失配 `Δε = ε_v − ε_w` 决定（`_r1_pairgeo2.py` 的 Hadamard 判据）。
【实测，66 对】`‖Δε‖_F/scale` 范围 **0.1830–1.7056**（中位 1.6776），而
**同惯习面（同 packet）的那 6 对恰好 = 0.1830 = 全库最小**（小 **9 倍**）
⇒ **同 packet 界面失配极小 ⇒ 共格低能**（且实测 `g3 = 0`，共格判据吻合）。

### 三、实现（**默认关 ⇒ 逐位不变**）

```python
γ_F2(v,w) = γ₀·[(1−λ) + λ·min(1, ‖Δε(v,w)‖_F / Δε_ref)]
```

* 新开关 `--f2-pair-gamma λ`（**默认 0.0**）；
* **λ = 0 ⇒ 不填 `gtab`**（保持 NaN）⇒ 引擎走原标量路径 ⇒ **逐位不变**；
  ⚠ **关键**：**不能**在 λ=0 时把 `gtab` 填成 `γ₀` —— 那会让 `facet_gamma_sub` 返回
  **数组**而不是标量，从而**换掉引擎的代码路径**（`windowB_lath.py:280` 的 `bad.all()`）。
  这条在代码注释里写死了。
* 改动落在 `windowB_lath.LathTable.__init__` + `summary()`（新增 `F2 配对 γ=` 标签）
  + `_bk_exp.build_table` / CLI。

### 六、⚠ 记账（**不预设"哪个对"**）
