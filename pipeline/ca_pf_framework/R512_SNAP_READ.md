# R512–R515 —— 补上任务(3) 验收的缺口 + 一次"假警报"的处理

> 2026-10-01 ｜ 依据：任务(3) 的验收要求「**新旧数据都能读**、量具自检 `FAIL = 0`、默认路径回归逐位不变」

## §1 缺口的发现：**int16 快照从来没存在过**

`_r512` 扫了归档里**全部 1976 个快照**，按 `region.dtype` 分层：

| dtype | 个数 |
|---|---:|
| **int8** | **1948** |
| **int16** | **28** |
| 其他 | 0 |

**第一次扫（`[:400]` 按字母序截断）时 int16 = 0 个** ⇒ 我当时以为"D1 FAIL"。
**真相有两层**：
1. 我的扫描**按字母序截断**，漏掉了字母序靠后的臂（**自查错误 #102**）；
2. **更重要的**：改动（R474）之后**所有冒烟臂都写着 `--snap-every 99999`**（不落快照）
   ⇒ **int16 快照确实一个都没有**；`abA` 则在改动**之前**就起跑了。

**⇒ 所以任务(3) 的"新旧数据都能读"这一条，此前**只验了写、没验读**。**
**⇒ 已补一个 120 步的小跑（`_r513`）产出 4 个 int16 快照**（`region` 与 `band_fld` 都是 int16）。

## §3 ⚠ 一次"假警报"：我差点报告"量具非确定"

D3 第一次跑**报 FAIL**：`f3_pos_n`、`f3_std_n` 两个字段"不同"。
**在 int8 臂上这两个调用的输入完全相同**（`astype(np.int8)` 是恒等）⇒
**只可能是量具不确定** —— 而用户的硬要求是「**一定确保测量工具的正确性**」，
若量具真的非确定，**所有基于 `f3_pos_*` 的结论都会带随机抖动**。

**⇒ 我专门写了 `_r514`（确定性检验）：同一输入连调 5 次，逐字段比对。**

### 3.1 真相：**是**我的比较**错，不是量具错（自查错误 #101）

那两个字段在两次调用里**都是 `NaN`**（该快照没有 F3 面 ⇒ 位置统计无定义），
而 **`nan != nan` ⇒ 我的比较函数把"两次都是 NaN"判成"不同"**。

**修好后（`_r514`）**：

```
E1 同一输入 5 次是否逐字段相同
   ✅ **全部 294 个字段逐位相同** ⇒ 量具是确定的
E3 负对照：改 1 个胞 ⇒ 输出必须变
   变化字段数 = 7 / 294 ⇒ ✅ PASS（量具有分辨力）
```

**⇒ 量具**是确定的**；抖动幅度的读数（`nan`）本身就在提示"这两个字段是 NaN"。**

### 3.2 ★ 这条教训要记住

**比较"量具的可复现性"时，必须先处理 NaN。**
`np.array_equal` 默认 `equal_nan=False`、`==` 对 NaN 恒 `False`
⇒ **"两次都是 NaN"会被误判成"不同"**。
**凡"逐位/逐字段比对"的判据都适用这条。**

⚠ **而且我在这上面**栽了两次**（#101 的第一刀只补了数组分支，**漏了标量分支**，
`f3_pos_n` 是 Python float ⇒ 第二刀才补上；`_r512` 里也是同样两刀）。
**⇒ 教训：改比较函数时要**同时**检查数组分支与标量分支。**

## §4 顺带确认的一件事

`abA` 的快照是 **int8**（它在 R474 之前起跑）⇒ 它的数据**没有问题**，
但**受 119 根板条的表示上限约束**（`nreg_used` 长期钉在 24）。
**⇒ 引用 `abA` 的"多少根/多少块"时必须带这条口径。**
