## §1 缺口的确切表述（读原文，不转述）

### 1.1 框架自己怎么说的

`windowB_closure.py:142-158`（C-2 推导）：

> ① 引擎几何：一次形核事件播一整片，**占满整个面内足迹** `A_f = L·W`
>   ⇒ "一个核最终占的面积" `A_0 ≡ A_f`（**这是几何恒等式，不是选择**）。
> ③ 板条数 = 面上的核数：`n = N_A·A_f = α_KM·(M_s − T_f)`
>
> ⚠ 记账：本条**只对"堆叠型块"成立**（每片占满同一足迹）。

`windowB_closure.py:89`（同一文件的另一处）：

> 冷得越深、板条越多、**块越厚**（`W_block = n·t`）

`windowB_closure.py:670-674`（`limitations()` 第 1 条，**必须随任何结论一起报**）：

> 'C-2 的 `n = α_KM(M_s − T_f)` 只在"堆叠型块"（每片占满同一足迹）上成立；
>  **面内并列的多个 block 需要在面内做分割，本轮不做。**'

**⇒ 三条合起来，语义是确定的：`n(T)` = 「**一个块**里沿堆叠方向摞起来的板条数」**
（块厚 `W_block = n·t`），**不是盒子里的总根数**。

### 1.2 实现怎么用的

`_bk_exp.py`（athermal 路径）：

```python
_Tnow = float(g.T)
_tgt = min(int(np.floor(CL.alpha_km_n_lath(_Tnow, _alpha) + 1e-12)), nv)
while n_ath_tgt < _tgt and n_ath_tgt < nv:
    ...
```

`n_ath_tgt` 是**全盒累计事件数**（`fresh` 建新块 + `stack` 往老块加，**混在一起数**）。

**⇒ 错配**：把「每块根数」当成了「全盒总根数上界」
⇒ **全盒最多 `n(T_end)` 次事件**；而且**块数越多、每块拿到的就越少**
（`K` 变大只是改分配，`_tgt` 不变）⇒ **对 `B>1`，每个块都拿不到 C-2 说的那个 `n`。**

## §2 ⇒ 正确的总量公式

设盒子在面内的横截面为 `S = L_box²`，单块的足迹 `A_f = L·W`，块数为 `B`。

```
① 块数上界（**几何导出，不是编的**）：   B ≤ S / A_f
   （每块占满一个 `A_f` 的足迹 ⇒ 面内最多平铺这么多块）
② 每块根数（C-2，框架已有）：           n(T) = α_KM·(M_s − T)
③ 总根数：                               N_tot = B · n(T)
④ 表示上界：                             N_tot ≤ nv      （任务(3) 已放到 32760）
⑤ 内存上界：  phi 是 (N_tot+1, N³)·(4 或 8) B
```

**⇒ `B` 是**输入**，不是预言。**
理由：框架**明写**不做面内 Voronoi 分割 ⇒ **没有"块数"的律**
⇒ 只能把它当**输入**，并**必须显式记账**（与 `--nuc-fresh-every` 同类）。

**⇒ 但它有一个**导出的上界**（①），这是本文件新增的、可证伪的内容。**

## §3 关键数字（10 µm 盒子，`N=160`、`Δx=62.5 nm`）

| 量 | 值 | 来源 |
|---|---|---|
| `L_box` | 10.0 µm | 任务(5) 要求 |
| 横截面 `S` | 100 µm² | `L_box²` |
| 单块足迹 `A_f` | `1000 × 500 nm` = 0.5 µm² | `--plate-L` / `--plate-W` |
| **块数上界 `B_max`** | **200** | `S/A_f` |
| 每块根数 `n(298 K)` | **24** | `α_KM·(873−298)` |
| 上界下的总根数 | 4800 | `B_max · n` |
| **C5 需要的根数** | **220–450** | `NEXT_TASKS_FOR_REVIEW.md §4.1` |
| ⇒ **对应的块数** | **B ≈ 10–19** | `220/24 … 450/24`（**远在 `B_max=200` 内**） |

**⇒ 内存（真正的约束）**：`phi = (N_tot+1, 160³)·w`

| `N_tot` | f64 | f32 |
|---:|---:|---:|
| 25 | 0.82 GB | 0.41 GB |
| **456**（B=19） | **14.9 GB** | **7.5 GB** |
| 1000 | 32.8 GB ❌ | 16.4 GB |

**⇒ ⇒ 结论：任务(5) 的目标配置是 `B ≈ 19` 块 × `n = 24` 根 = **456 根**，
在 `N=160` 上 **f32 占 7.5 GB**（22 GB 预算内 ✅）、f64 占 14.9 GB（偏紧）。**

## §4 为什么这**不是**"编一条律"

| 担心的 | 事实 |
|---|---|
| "块数是新编的律？" | **不是**。`B` 是**输入参数**，与 `--plate-L`/`--nuc-init` 同类；**框架明说它没有这条律**，本文件**不发明律**，只**把输入暴露出来 + 给出几何上界** |
| "那 C5 还算'涌现'吗？" | **部分不算**。块的**数目**是规定的 ⇒ 「填满盒子」是**规定的**；但**每块内部**（堆叠、F3 面、变体选择）与**块之间**（谁碰谁、是否协调）**仍是涌现的** ⇒ **C3/C4/C6 不受影响**。**这条必须随结论一起报。** |
| "为什么不直接调 `α_KM`？" | `α_KM` 有出处（KM 律）⇒ 调它是**改物理**。`B` 是**未被建模的自由度**⇒ 把它当输入是**诚实的**。 |

## §5 实现规范（**下一步才写代码**）

* **新开关** `--nuc-block-target B`（**默认 0**）。
  * `B = 0` ⇒ **完全走现在的路径**（`_tgt = min(floor(n(T)), nv)`）⇒ **逐位不变**；
  * `B > 0` ⇒ `_tgt = min(B · floor(n(T)), nv)`。
* **必须落盘**：`B` 经 `vars(a)` 入 `meta.json`（与 `--nuc-fresh-every` 同样的留痕要求）。
* **必须打一条启动横幅**：明确写「**块数 `B` 是输入、不是涌现**」，
  并给出该配置下的 `B_max = S/A_f` 以便判"是否在几何上界内"。
* **`--nuc-fresh-every K` 的关系**：`K` 决定**每 K 个事件建 1 个新块**；
  要让 `B` 个块各拿到 `n(T)` 根，应取 **`K = n(T)`**（每 `n` 个事件建一个新块）。
  ⇒ 两个开关**必须一起用**，且**文档要写清这个搭配**。

### 7.1 验收（`_r503`，四臂 A/B，`N=48` ⇒ `B_max=18`、`n(500 K)=15.6`）

| 臂 | `B` | athermal 事件 | `nreg` | 超界告警 |

| # | 判据 | 结果 |
|---|---|---|
| **B1** | `B=1` 与 `B=0` 事件数相同 | ✅ **PASS**（4 vs 4） |
| **B2** | `B=8` 的事件数 > `B=0` | ✅ **PASS**（**8 vs 4**，上限 16→48） |

**⇒ `--nuc-block-target` 可用。**
⚠ **仍必须随任何结论一起报**：**块的数目是输入、不是涌现**
（框架 `limitations()` 第 1 条明写"面内并列的多个 block…本轮不做"）
⇒ **C5「填满盒子」是"规定出来的"，不是"涌现出来的"**；
但**每块内部的堆叠/F3/变体选择**与**块之间的相互作用**仍然是涌现的 ⇒
**C3/C4/C6 不受影响。**

### 7.2 ⚠ 一条读数上的注意

`B=8` 臂的 **`nslab_n` 仍是 4**（不是 8）—— `nslab_n` 数的是**聚合后的板条数**，
不是事件数。**不要把 `nslab_n` 当成"放了几根"。** 事件数看 `athermal 形核` 行数。
