**被否掉的路（记账，免得重走）**：
* **`Lam` 转置布局无收益**（1.03×）—— Linux numpy 2.5 的 `einsum` 已经不吃这个亏

* **手工展开 36 项更慢**（einsum 的向量化更好）。

## §4 ★★★ 本轮最重要的发现：Nyquist 面的**隐性 Hermite 投影**

### 4.1 症状
`_r562` B4 报"新的 σ 整链"与旧路差 **6.33e-2**（占 `max|σ|`，够大，不能忽略）。
而 B3 已证 `rfftn`/`irfftn` 本身只差 3e-16 ⇒ **差异不在 FFT**。

### 4.2 隔离（`_r566_b4iso.py`，每段都逐位钉）
```
C1  Kh 与 pf.K 的半子集            max|Δk| = 0.000e+00   ✅ 逐位
C2  LamH 与 Lam 的半子集            max|Δ|/max = 0.000e+00 ✅ 逐位
C3  rfftn(e) vs fftn(e)[..., :half] 1.436e-18            ✅
C4  irfftn(半谱) vs real(ifftn(全谱)) 4.155e-16           ✅
C5  einsum 两种布局                  0.000e+00            ✅ 逐位
C6  同一个 sh，两种逆变换              6.330e-02            ❌ ← 真因在这里
```
**⇒ 所有输入逐位相同，差异只能来自"怎么从谱回到实空间"。**

### 4.3 机理（这是旧代码里一直存在、但没人写下来的东西）
`sig = real(ifftn(−Λ ⊙ fftn(ε)))` 里的 `real(...)` **一直在隐式做 Hermite 投影**：

```
real(ifftn(X)) = ifftn( ½(X + conj(X∘mirror)) )        （mirror: k → −k）
```

而 `sh = −Λ⊙Eh` 在**三个 Nyquist 面**（i=N/2 / j=N/2 / m=N/2）上**不是 Hermite 的**。
原因：`kv[N/2] = −π/dx`，它的负 `+π/dx` **不在格点上**；索引镜像 `(N−i)%N` 把
N/2 映回自己，于是 `κ(mirror k) ≠ −κ(k)`（实测 `max|Δκ| = 4.02e+02`），
**`Λ` 是方向的函数**，所以 `Λ(κ(mirror)) ≠ Λ(κ)`（实测 `|ΔΛ|/max|Λ| = 3.25e-01`）。

`irfftn` 用的是**未投影**的半谱 ⇒ 两条路在 Nyquist 面上给出不同的实空间场。

### 4.4 精确修法（`_r567_nyqfix.py`，**热路径零代价**）
```
H[k] = ½(sh[k] + conj(sh[mirror k])) ,  sh[mirror k] = −Λ(κ(mirror k))·conj(Eh[k])
⇒  H = −½(Λ(κ) + Λ(κ(mirror))) ⊙ Eh
```
而非 Nyquist 面上 `κ(mirror k) = −κ(k)` **逐位**成立 ⇒ `Λ` 相同 ⇒ 修正项**逐位为 0**。
**⇒ 只需在建引擎时把 Nyquist 面的 Λ 换成两者平均，热路径一个字节都不多花。**

判决：
```
N1  irfftn(−Λ_eff⊙rfftn(e)) vs real(ifftn(−Λ⊙fftn(e)))   6.081e-16   ✅ PASS
N2  负对照：不做 Nyquist 修正                              6.330e-02   ✅ 有分辨力
N3  修正项在非 Nyquist 面                                 0.000e+00   ✅ 逐位为 0
N4  整链 0.0499 → 0.0292 s                                1.71×
    谱内存 (6,N,N,N)c128 12.0 → 6.2 MB；Λ 常驻 72.0 → 37.1 MB（288 → 144 B/胞）
```
Nyquist 面占半谱的 **6.04%**（N=64：8160/135168）。

**⇒ 顺带记账（对物理的含义）**：旧代码在这三个面上把 σ 投影成 Hermite 的，
新代码若不做修正则等价于"在 Nyquist 面用了另一个 Λ"。**旧行为才是自洽的**
（实值应力场必须 Hermite），所以修正的方向是**让新路复现旧路**，而不是反过来。
这条以前**没有任何文档写过**，属于本轮新增的模型认识。

## §5 落地的三项改动（全部新开关、默认关）

### 5.1 `pf3d.PF3D(..., eps0_mode='loop'|'einsum'|'gemm')`
* `'loop'`（默认）：原 `6×nv` 次整场 `+=`。
* `'einsum'`：`np.einsum('vp,v...->p...', e0v, phi)` —— **逐位相同**、1.76×。
  逐位相同这条**在两个宿主上各测过一次**（numpy 2.1.3 与 2.5.3 都给 `0.000e+00`）。
* `'gemm'`：`e0v.T @ phi.reshape(nv,-1)` —— 微基准 18.1×，但**在真实引擎里反而慢**
  （`rfft+gemm+gather` 0.2915 > `rfft+einsum+gather` 0.2524）。
  **【推断，未单独隔离】** 与 `ParCtx` 线程池争 BLAS 线程有关；未做单变量实验，故只记账不下结论。

### 5.2 `pf3d.PF3D(..., fft_mode='c2c'|'rfft')`
* `'c2c'`（默认）：`fftn`/`ifftn` 全谱。
* `'rfft'`：`rfftn`/`irfftn` **半谱**，`Lam` 只存半谱并带 §4.4 的 Nyquist 修正。
  半轴 = **最后一个轴**（实测），半谱形状 `(6,N,N,N//2+1)`。
  收益：整链 1.71×、谱内存减半、`Lam` 288 → 144 B/胞（**对任务(5) 的 10 µm 内存墙直接有用**）。
  **不是逐位**：σ 差 2.2e-16（f64 舍入地板）⇒ **归档复现必须用默认 `c2c`**。

### 5.3 `surface.LevelSetMulti(..., ed_pair_mode='full'|'gather')`
* `'full'`（默认）：旧路 —— 造 `(nreg,N³)` + `nreg` 次 einsum + 2 次 `take_along_axis`，
  而下游**只用 winner/runner-up 两行** ⇒ `nreg−2 = 12` 行白算。
* `'gather'`：只算那两行。实测 **4.92×**，且 `ed[karr]`、`ed[larr]` **逐位相同**
  （用**同一个** `np.einsum('p...,p...->...')` 调用 ⇒ 沿 `p` 的归约次序不变）。
  顺带把 soft 分支提取成**唯一实现** `_soft_sigma()`（`elastic_driving` 与快路共用，
  防两处分叉 —— `AGENTS §3.24`）。

### 5.4 ★★ R570/R571：`E_el()` 的半谱**配对权重**（**冒烟在真实路径上抓到的缺陷**）

单元判据（V1）只查了 `sigma_tensor`，**没查诊断能量 `E_el()`**。
`_r569_smoke.sh` 一跑真实 `_bk_exp.py`，`E_el_J` 立刻差 **37.7%**。

机理：`E_el` 是**全谱**二次型 `Σ_k q(k)`，`q(k)=Re(conj(ε(k)):Λ:ε(k))`。
半谱求和必须带**配对权重**。`_r571_elcheck.py` 在 N=32 上把权重直接量出来：

| 权重方案 | `Σ_half w·q / Σ_full` |
|---|---|
| `w=2` 全体（第一版） | 1.0631 |
| `w=1` 当 `i/j/m` 任一 `=N/2`（第二版） | 1.00047 |
| **`w=1` 当 `m∈{0,N/2}`** | **1.00000000** ✅ |
| `w=1` 当 `m==N/2`（= mirror 仍在半谱） | 1.00101 |

（`m` = **半轴（最后一个轴）** 的索引；「另一半」= `m∈[N/2+1, N−1]`
⇒ `Σ_full q = 2Σ_half q − Σ_{m=0} q − Σ_{m=N/2} q`。）

**反直觉的一条（实测确认）**：`q` 必须用 **`Λ_eff`（带 Nyquist 平均的那个）**，
**不是**未平均的 `Λ_true` —— 同权重下 `Λ_true` 给 `1.00101`、`Λ_eff` 给 `1.00000000`。
（原因：Nyquist 面上 `k` 与 `mirror(k)` 互为负，`q_eff(k)+q_eff(mk)` 恰好等于全谱那一对的和。）
⇒ **`Λ_eff` 同时服务 σ 与能量**，不需要额外存 `Λ_true`。

修后：`V1b E_el()` c2c=3.761802e+05 / rfft=3.761802e+05，**相对差 3.095e-16** ✅。

## §10 ★ rfft 的**决策量具**（`_r574_rfft_decision.py` / `_r575_buildtime.py`）

### 10.1 收益（交错 5 轮配对，消机器漂移）

| 臂 | s/步 | 相对上一行 |
|---|---|---|
| A `loop/full/c2c` | 0.3067 | 1.00× |
| B `einsum/gather/c2c` | 0.2715 | **1.130×** |
| C `einsum/gather/rfft` | 0.2414 | **1.125×**（rfft 的**边际**） |

（配对差本身散布 6–14%，说明单步墙钟仍不足以支撑更细的结论。）

* **建引擎快一倍**（`_r575`，交错 3 轮，N=64）：c2c **10.42 s** → rfft **5.30 s**，

* **内存**：`Λ` 288 → **148 B/胞**（N=64：72.0 → 37.1 MB）；σ 链瞬时 48 → 25 MB；
  `_wmask` 0.52 B/胞。
* **确定性** ✅：`rfftn`/`irfftn` 在 `workers=4` 下连跑两次**逐位相同**。

### 10.2 代价

* **不是逐位相同**（唯一有物理意味的代价）：σ 差 **2.227e-16**、`E_el` 差 **3.095e-16**
  ⇒ f64 舍入地板。**数学上精确**（Nyquist 修正是精确的，非近似），
  但**长轨迹会因混沌分叉** ⇒ **归档复现必须用默认 `c2c`**。
* **多出一套要并行维护的路径**（`_rfft/_irfft`、半谱 Λ + Nyquist 平均、`E_el` 配对权重、
  半谱 k 网格、`_wmask`）。**这个风险本轮已兑现三次**：
  ① `E_el` 漏配对权重（差 37.7%，单元判据全绿时被真实路径冒烟抓到）；
  ② 我误以为 `Λ_true` 才对（`_r571` 实测推翻）；
  ③ **白算全谱表**（rfft 建表 +7.4 s，`_r574` D2 抓到；已修，见 §10.3）。
* ⚠⚠ **内存收益我先前夸大了**。原话"直接缓解 C5 内存墙"**不成立**。
  按内存定律【推算，未实测】：N=160 时 f64 `nv_max` **359 → 368（+2.5%）**、
  f32 **479 → 491（+2.6%）** —— 因为固定项只占总量的 ~5%
  （nv=359 时固定 1218 MB vs 边际 22437 MB）。**真正的 C5 杠杆是边际项 `a`**
  （`φ` 的 8 B/胞 × nv），即 `phi_prec='f32'`（**359 → 478，+33%**），那是另一个决策。
* `_wmask` 依赖"半轴 = **最后一个轴**"这一 scipy 实现细节 —— **目前只在注释里，
  没有断言**，应补。
* 模块内并存两套 FFT 约定（`_fft/_ifft` 仍服务 `step()`/`E_chem_grad`）⇒ 维护陷阱。
