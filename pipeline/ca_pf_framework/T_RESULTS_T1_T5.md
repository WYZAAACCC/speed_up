>    **修法一行**：`κ_winner = σ·div(∇(σΔφ)/|∇(σΔφ)|)`（两条路径各一处，已落盘）。

### T11d —— 逐个排除：**梯度不是原因**，病灶锁定在 `coef` 的配对符号构造（`_probe_grad_stair.py`）

**推理链（本轮的关键一步）**：T11c 的算例里 `γ=0`、`pf=None` ⇒

方程退化为 `φ_t + c|∇φ| = 0`（`c = MΔf` 常数），精确解是**纯平移**，
**前提是 `|∇φ| ≡ 1`**。⇒ 倾斜档的赤字只能来自"离散 `|∇φ|` 在阶梯上 ≠ 1"。

**实测（直接构造 SDF `φ = (x−c)·n` 量带内 `|∇φ|`）**：

⇒ **梯度假设被推翻**：`|∇φ|` 在**两种法向、两种格式、五档 Δx** 下**都恰好是 1.0000**
（`|∇d|` 恰好 2.0000）。所以"离散梯度在阶梯上被低估"**不是**原因。

**⇒ 剩下的唯一嫌疑：`coef` 的配对符号构造。**

代码里（非 `pair_kernel` 分支）：

```python
v_at  = np.where(iface, vcanon, 0.0)
kat, lat = karr[tuple(ind)], larr[tuple(ind)]          # 最近界面胞的配对
same_pair = ((karr==kat)&(larr==lat)) | ((karr==lat)&(larr==kat))   # ← 接受**两种次序**
band = (dist <= band_cells) & same_pair
coef = np.where(band, sigma * v_at[tuple(ind)], 0.0)   # ← sigma 取**本胞**的次序
```

`coef = sigma_本胞 × vcanon_最近胞`。**跨过界面时 `karr/larr` 的次序会翻转**
（一侧 winner 是 1、另一侧是 0）⇒ `sigma_本胞` 相对 `sigma_最近胞` **变号**。

* **轴对齐前沿**：一个非界面胞的"最近界面胞"**总在同一侧** ⇒ 次序一致 ⇒ `coef` 正确
  ⇒ 实测 **1.0000**（散布 0.98%）✓
* **倾斜前沿**：阶梯的最近面片常在对角方向、**跨到另一侧** ⇒ `same_pair` 因接受两种
  次序而放行，但 `sigma_本胞` 与种子的次序**相反** ⇒ `coef` 变号 ⇒ 前沿被"拉平/拖慢"
  ⇒ 实测 0.52–0.67、且随 Δx 恶化 ✓

这是**可检验的预测**，下一轮直接验：把 `same_pair` 收紧为**次序敏感**（或把 `sigma`
一并纳入延拓量，使 `coef` 与被延拓的规范形同源），若倾斜档恢复到 1.000 且轴对齐档
仍 ≤1%，则确诊并修好。

### ★★ T11-C 的失败是**真问题**，且指向一个已知缺陷

`γ_eff/γ ≈ 6`（球长到 1850 nm 而非平衡的 300 nm）⇒ **Gibbs–Thomson 平衡没建立**。
按 `Δf = γ·2/R`，平衡半径应为 300 nm，但球在 R > R_eq 后**仍继续长大**
⇒ 界面上的曲率项被**低估约 6 倍**。

**这与仓库注释里登记的 EXPERT-#4 完全吻合**：`pair_kernel=False`（默认）时，
变体-变体界面的曲率取的是 **winner 场的曲率**而不是**差分场 `d = φ_k − φ_l` 的曲率**，
⇒ 界面**两侧不对称**：
* 内侧（winner = 区域 1）：`κ = div(∇φ_1/|∇φ_1|) = +2/r` ✓
* 外侧（winner = 区域 0）：`κ = div(∇φ_0/|∇φ_0|) = −2/r` ⇒ **符号翻转**

⇒ 两侧的 `−γκ` 项一正一负、**互相抵消**，净效应只剩约 1/6
⇒ 曲率驱动被系统性削弱 ⇒ 球停不下来。**这是一条可算的、可验的缺陷**，
不是测量问题。

产物：`_t11g.log`、`T11g_dx.py`。

### ★★ 新发现的 bug：差分场的**符号**必须按**区域编号**定向，不能按 winner/runner-up

我写的是 `d = φ_karr − φ_larr`。而 `karr/larr` **跨界面会互换**
（内侧 winner=1、外侧 winner=0）⇒ `∇d` 的**方向跨界面翻转** ⇒
`div(∇d/|∇d|)` **跟着翻号**：

* 内侧：`d = φ₁−φ₀ = 2(r−R) < 0`，`∇d = +2r̂` ⇒ `κ = +2/r` ✓
* 外侧：`d = φ₀−φ₁ > 0`，`∇d = −2r̂` ⇒ `div(−r̂) = −2/r` ⇒ `−γκ > 0` ⇒ **反而加速**

⇒ 我那个"修法"复现了与旧写法**同一种病**，只是换了个位置。
**正确做法：按区域编号定向** `d = σ·(φ_karr − φ_larr)`，`σ = where(karr<larr, +1, −1)`

⇒ 下一轮：把 `d` 按 `σ` 定向（同时修 `pair_curvature` 与 `pair_kernel` 两条路径），
判据重跑：`γ_eff/γ → 1`（临界半径法）+ 回归守卫（T11-A′ 速度、T11-B 面积不退化）。

### ★★ 但更要紧的是：**`wrap_axes(k=None)` 的语义是错的（守卫过度触发）**

`wrap_axes(None)` 判的是"**所有变体区域的并集**是否周期贯通"。
而**碰撞之后**，变体网络本来就会**渗流贯通**（这正是 impingement 的定义！）
⇒ 它把"**网络已连通**"误报成"**某条板条绕盒**"。

**正确的判据是"逐变体"**：只有当**某一个变体**的区域自身贯通周期盒，
才说明那条板条绕盒了。⇒ **守卫要按 `k` 逐变体查**（`any(wrap_axes(k) for k in 1..nv)`），
而不是查并集。

**这条修正对 T12-D12a 的正对照仍然成立**（那里用的是单个区域 `k=1` 的薄层与球），
但**在 T13/T16 这类多核算例里必须改成逐变体**。
⇒ 与 `T16` 的 RVE 重设一起做（T16 那次"`f=0.03` 就绕盒"的读数，
很可能也是并集渗流误报，而不是板条真的绕盒 —— **需要用逐变体口径重判**）。

### 守卫语义修正的验证（`T12_verify_wrap2.py`）—— 三个对照，结论有边界

| 对照 | 并集口径 `wrap_axes(None)` | 逐变体 `wrap_axes_any()` | 期望 |

| **负对照 2**：2³ 小块棋盘（**物理**：并集满盒、单变体不连通） | [0,1,2]（误报） | **{}** ✓ | 为空 ⇒ **PASS** |

**⇒ 判据的正确语义边界（记账）**：

1. **对物理构型（连通斑块）逐变体口径是对的**：负对照 2（等价于"碰撞后网络渗流"）
   与正对照都通过 ⇒ **修正有效**，`T16` 的"绕盒"读数要按它重判。
2. **对"每胞随机"这种非物理构型它也会报** —— 因为此时"某个变体自身贯通周期盒"
   在**周期图**的意义上确实成立（随机集在 8.3% 占位下跨面成键）。
   ⇒ 这不是 bug，而是**判据的适用前提**：**假设每个变体的区域是连通的物理斑块**。
   已写进文档，避免将来误用。
3. **并集口径 `wrap_axes(None)` 在有多个变体时不可用于"板条是否绕盒"** ——
   它判的是"网络是否渗流"，那是 **impingement 的定义**，不是缺陷。

## T25-B ★★★ 厚度天花板：**与预算、与量具都无关的纯比值论证**

`M(n) = M0·exp[−β_h(n·n*)² − β_w(n·w)²]` 里，`Δf`、`M0`、`dt` **全部约掉**，只剩比值：

```
厚向长大速率 / 面内长大速率  =  exp(−β_h)  =  e^(−3.5)  =  0.0302      （精确，与任何测量无关）
```

板条在面内能走多远，由 R9（晶核不重叠）与 impingement 定：

| 量 | 值 |
|---|---|
| 面内可用距离 `d/2 − R_seed` | **500 nm** |
| ⇒ 碰撞前增厚上限（用**精确比值**） | 500 × 0.0302 = **15.1 nm** |
| ⇒ **板条厚上限（按模型比值）** | **≈ 215 nm** |
| ⇒ 上限（用**实测**实现比值 ~5，见下） | 500 / 5 = **100 nm** ⇒ **≈ 300 nm** |
| ⇒ **稳健结论** | **`t ∈ [215, 300] nm`** |
| 文献 as-built LPBF α′ 板条厚 | **510–880 nm** |
| **差距** | **1.7–4.1×，且不随运行时长改善** |

**实测的实现比值**（`_probe_seedstat.log` §C）：面内半径 **1.1–1.3 nm/步**，
厚向 **0.226 nm/步** ⇒ 实现各向异性 **≈5**（模型名义值 33）。
⇒ 面内比设计慢、厚向与设计吻合，故真实上限偏向 **300 nm** 一侧。

**★★ 决定性反算**：若坚持"靠单核长大把厚度做到 700 nm"，需要
`d/2 − R_seed ≥ (700−200)/0.0302 = 16.6 µm` ⇒ `d ≥ 33.8 µm` ⇒ 盒子下限
`L ≥ 4d = 135 µm` ⇒ `N = 135 µm / 50 nm = **2700**` ⇒ **1.97×10¹⁰ 胞 ≈ 17.6 TB**。

> ⇒ **结论：在当前"只在 t=0 形核、此后只长大"的框架里，
> 文献量级的板条厚度在任何可负担的分辨率下都达不到 —— 不是参数没调好，是机制缺一半。**
