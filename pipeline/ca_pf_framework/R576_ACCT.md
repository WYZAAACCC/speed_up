## §1 做了什么：钩子进生产代码

`_r561_opfacct.py` 用 monkey-patch **只能包函数**，包不到 `advance()` 函数体里的表达式 ——
而那正是 22.9% 未归属所在。⇒ 新增 `windowB_acct.py`（零依赖、~300 行），
并在 `windowB_surface.py` / `windowB_pf3d.py` / `windowB_par.py` 里埋点：

| 类别 | tag | 挂在哪 |
|---|---|---|
| **`_rfft`/`_irfft`** | `el.rfft_fwd` / `el.rfft_inv`（另补 `el.fft_fwd/inv`、`el.epsh(_r)`、`el.sig.contract`、`el.sig.real`、`el.e0.*`） | `windowB_pf3d.py` |
| **`_geom_k` 内部** | `adv.geom.mask_bbox` / `.grad` / `.curv` / `.stiff` / `.scatter` | `_geom_k` 函数体 |
| **`_step_k` 内部** | `adv.step.vnk` / `adv.step.advphi` | `_step_k` 函数体 |
| **速度律** | `adv.vel_law`（`dG_cell = Δdf + Δed − γκ`） | `advance():dG_cell` |
| **`argmin2` 内部** | `argmin2.winner` / `argmin2.runnerup` | `windowB_par.ParCtx.argmin2` |
| **`advance` 自身表达式** | 22 个互斥顶层 tag（见 §3 表） | `advance()` |
| **`upwind_flux_vec` 内部** | `op.ufv.body` / `.diff` / `.minmod` / `.where` | 模块级算子 |
| **构造期** | `build.PF3D` / `build.lam.c2c` / `build.lam.rfft_*` / `build.kgeom` / `build.ncmp` / `build.e0v_eng` + `.bytes` | `PF3D.__init__` / `LevelSetMulti.__init__` |

### §1.1 两个设计决定（都是被实测逼出来的）

1. **关闭时必须是"一次函数调用"而不是零**：`mark(tag)` 关闭时返回单例 `_NOOP`，
   `with` 再调 `__enter__/__exit__`。**微基准实测 201 ns/钩子点**（§4）。
2. **并行安全**：`_geom_k` / `_step_k` / `argmin2` 的 worker 里也有钩子。
   `dict[k] = dict.get(k)+dt` **不是原子的**（GIL 只保单个字节码）⇒ 每个线程一个累加器
   （`threading.local` + 注册表），报告时合并。**共享一个 dict 会让并行段的账静默偏小。**
3. **`span_begin`/`span_end` 必须按 tag 配对，且缺配要能被看见**：v1 用**栈**，
   一旦块内提前 `return`/抛异常就少弹一层 ⇒ 之后**每一次** `span_end` 都把时间记到**别人的 tag** 上，
   而表面完全正常。⇒ 改成按 tag 配对 + `acct.corrupt()` 非空即报告拒下结论。
   **正对照**：`_r576_check.sh` C5 "故意只 begin 不 end" ⇒ 必须报出来（第一版 `corrupt()` 只报
   "`span_end` 无配对"，对这个正对照返回 `[]` ⇒ **自检静默通过**，已修）。

### §3.1 本轮最大的单个发现

**`adv.mirror_check`**：`advance()` 的默认路径里有一段

```python
if (not getattr(self, '_mirror_checked_step', None)) or True:   # ← `or True` 恒真
    ... self.par.gradient(pha) ; self.par.gradient(phb) ...
```

**`or True` 使它每步都跑**，而它**只**产出 `_pair_mirror`/`_pair_scale` 两个诊断标量（外加一条告警）。
它是**纯记账、不参与任何数值**。在本算例上 0.8 ms（0.2%）；当 `(karr>0)&(larr>0)` 的胞数
大于 0 时它要跑**两次整场梯度**（对照 `adv.geom.grad` 4 次 = 27 ms ⇒ 两次 ≈ 13 ms ≈ **3.5%**）。
仓库注释自己写着"首版只在第一次 `advance` 时量一次（那时种子还没碰撞）" —— 说明**当初是为了诊断**
才放开的；现在应该把它**门控**（默认关或低频），但要**单独立项、单独逐位对照**。

## §4 钩子代价（微基准，不是端到端推的）

`_r576_hookcost.py`（`N=3e5` 次/轮 × 7 轮取最小）：

| 项 | 实测 |
|---|---|
| 关闭时 `with acct.mark('x'): pass` | **201 ns/次** |
| 关闭时 `span_begin+span_end`（折半） | 49 ns/钩子点 |
| 打开时 `with acct.mark('x'): pass` | 699 ns/次（= 计时器真实开销） |
| **钩子执行次数** | **520 次/步**（`_r576_prof.py` 实测） |
| **折算单步开销** | **0.29 ms = 0.029%** ✅（判据 ≤0.5%） |

### §4.1 为什么不用端到端 A/B 当主判据（**必须记账**）

`_r576_bench_one.py` + `_r576_acct_cost.sh` 用**导入期源码剥离**造了真正的"零钩子"臂
（`with acct.mark(...)` → `if True:`；`span_*` → `pass`；不重排缩进）。实测：

```
每轮 overhead = [+12.08%, +0.37%, +5.16%, -14.28%]   中位 +2.76%
```

**区间盖住了 0** ⇒ 这个量具的信噪比 < 1，**判 1% 的效应不合格**。
根因：每一臂都要**重建引擎 30–60 s**，而本机是笔记本，在这段时间里就漂了。
⇒ **改用微基准（直接量每次调用）+ 计数（每步次数）**，两项都是实测，没有噪声。
端到端 A/B 只作参考保留。

## §8 宿主人力指纹（**本轮新增的纪律，必须固化**）

新建 `_r576_hostfp.py`：`py_loop`（纯 Python 单核）、`np_axpy`（单核带宽）、
`np_matmul`（多核 BLAS）三个探针，取多次最小值。

当前宿主（WSL2 / i7-14700HX）：`py_loop≈0.115–0.140 s  axpy≈16–19 GB/s  matmul≈112–167 GFLOP/s`。

**为什么必须有**：本轮我一度以为"机器慢了 2.4×"（`build.lam.c2c` 6.39 s → 15.6 s），
**实际是我拿 N=48 的数去比 N=64 的数**（O(N³) ⇒ (64/48)³ = 2.37×，正好对上）。
**这条差点写成一个不存在的"宿主漂移"结论** —— 与 `AGENTS.md` 教训 23/24 同族：
**先把口径对齐，再谈差异。**

同时确认了**跨会话的绝对秒数不可比**：本会话同一份代码同一命令的单步墙钟
从归档的 0.2980 s 变成 0.4501 s（1.51×），而逐步回归的 `s/步` **一字不差**。
⇒ **凡跨会话比较，必须交错配对；单臂绝对值只能当量级参考。**
