## §1 ★ 我本阶段**自己犯的一个量具错**（按用户要求先记录）

**症状**：我读了 abA 的 `series.csv`，把 `wall_s` 列**求和**，得 **3,832,811 s = 1064.67 h（44 天）**。
**真相**：`wall_s` 是**累计列**（从 0 单调增至末行）⇒ 总历时 = **末行值 27,717 s = 7.70 h**。
**⇒ 错因**：把**累计列**当**增量列**。
**⇒ 纪律**（并入本 goal 的量具清单）：**报"总量"前先判这一列是累计还是增量**
（判据：单调递增 + 首值 ≈ 单步耗时 ⇒ 累计）。与既有 P30（同名量不同单位）、
P20（守恒量做差有噪声地板）**同族**。
**✅ 本文件及后续一律用 7.70 h / 4.68 s·步⁻¹。**

## §2 ★★ 驱动力：逐行核实（用户点名的那一类简化）

### §2.1 证据链（全部**读到源码**，非推理）
| 环节 | 位置 | 逐字 |
|---|---|---|
| **温度钟** | `_bk_exp.py:1040` | `_T_of_t = KM.linear_cool(_Tstart, _Tend, (_Tstart - _Tend) / _q)` |
| **驱动力函数** | `_bk_exp.py:1041` | `_dG_of_T = (lambda T: KM.drive_of_T(T, T0_TI64, DS_REF))` |
| **注入引擎** | `_bk_exp.py:1152` | `dG_of_T=_dG_of_T, T_of_t=_T_of_t,` |
| **每步更新** | `_bk_exp.py:2295` | `g.set_T(g.T_of_t(g.t))` |
| **唯一入口** | `windowB_surface.py` `set_T` | docstring 逐字：**「★ T6：这是**唯一**把温度变成驱动力的入口」** |
| **赋值** | 同上 | `self.df[1:] = float(self.dG_of_T(self.T))` |
| **消费** | `windowB_surface.py:4342/4364/5091` | `self.df[k] - self.df[lk]`（场间驱动力**差**） |

**⇒ 结论（【核实：代码层】）**：**驱动力**随温度**、且**每步**更新，**不存在**"把驱动力当常数用在整个冷却段"。
abA 的 `meta.json` 也印证：`nuc_law=athermal`、`alpha_km=0.041739`、`cool_rate=2.3524e6`、`T_end=298`。

### §2.2 ★ 但**同类简化确实存在**，只是不在我原先以为的位置
**真正的简化是**温度历史**：`linear_cool` ⇒ `T(t) = T_start − q·t`（**线性**降温）。
* **代码自陈**："占位"（见 `R581_SIMPLIFICATION_AUDIT.md §5`，登记为 **S14 / N2**）。
* **物理代价**：LPBF 的真实热史是**快速升温 → 峰值 → 快速凝固 → 多道次回火**，
  不是单调线性降温。**线性降温会改变**：①形核温度窗口的顺序与宽度；
  ②`alpha_km·(M_s − T)` 的到达时刻；③自协调变体的选择序列。
* **计算收益**：零（它**不省算力**，只是"还没有真实热史可用"）。
* **⇒ 按你的判据（代价 > 收益 ⇒ 按物理正确的方式实现）**：**这一项应当换掉**；
  但**真实热史是 Window A（熔池尺度）的产物**，属**跨窗口依赖**。
  **⇒ 处置见 §4.1（我需要先确认 Window A 有没有可用的热史产物）。**
