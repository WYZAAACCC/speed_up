# R598 —— N=160（10 µm 盒）的 **nv 上限实测**

> 日期：**2026-10-04** ｜ 方法：**两点实测**（不靠外推）
> 工具：`_t5_nvprobe160b.sh`（`/usr/bin/time -v` 取 `Maximum resident set size`）
> 日志：`_w2_t5_nvprobe160b.log`

---

## 1. 实测结果（N=160，`--nvar 1 --m M`，f64 + `pf-phi` 物化 = **当前生产档**）

| nv | 峰值 RSS | kB | 用时 |
|---|---|---|---|
| **16** | **4.73 GB** | 4,957,244 | 4:43 |
| **48** | **6.91 GB** | 7,245,180 | 5:39 |

### ⇒ 拟合出的**实测定律**

```
RSS(N=160) ≈ 3.64 GB  +  69.8 MB × nv
```
* 斜率 `(7245180 − 4957244)/32 = 71,498 kB/nv = **69.8 MB/nv**`
* 截距 `4957244 − 16×71498 = 3,813,276 kB = **3.64 GB**`

## 2. ★ 更正我上一轮给您的数字（**128 太保守**）

我上一轮用 `_t5_nvmax_calc.py` 报的是 **N=160 生产档 nv_max ≈ 128**，那**偏低**。
错在哪：我把实测的 **2.4× RSS 超配因子乘到了整个模型上（含斜率）**。

实测量出来的真相是：**超配只发生在"截距"那一项，斜率几乎就是数组字节本身**：

| 项 | 数组模型 | 实测 RSS | 比值 |
|---|---|---|---|
| 每 nv（斜率） | 62.5 MB | **69.8 MB** | **1.12×** |
| 固定项（截距） | 1.41 GB | **3.64 GB** | **2.58×** |

⇒ 差额（构造期临时量 + FFT 工作区 + 解释器）几乎全是**固定开销**，**不随 nv 增长**。

## 3. 因此：N=160 的 nv 上限

| 预算 | nv 上限（按实测定律） |
|---|---|
| **22 GB（22528 MB，全用满）** | **≈ 270** |
| 20 GB（留 2 GB 余量） | **≈ 240** |
| 18 GB（留 4 GB，可与其他作业并存） | **≈ 210** |

**其他档位**（斜率按 `a` 的比例缩放，实测斜率 69.8 MB ↔ `a=16 B/胞/nv`）：

| 档 | 每 nv（N=160） | 22 GB 下 nv 上限 |
|---|---|---|
| **f64 + 物化（当前生产档，**实测**）** | **69.8 MB** | **≈ 270** |
| f32 + 物化 | ≈ 52.4 MB | ≈ 360 |
| f64 + onfly | ≈ 39.3 MB | ≈ 480 |
| **f32 + onfly** | **≈ 21.8 MB** | **≈ 870** |

## 4. 对本决策（方案 a：N=160、`nv = B·n = 3×23 = 69`）

```
RSS = 3.64 GB + 69 × 69.8 MB = 3.64 + 4.82 = **8.46 GB**
```
⇒ **占 22 GB 预算的 38%**，非常宽裕。即使截距被低估 2 倍，也只需 ~12 GB。
**⇒ 方案 (a) 在内存上完全可行，且余量足够同时再跑一道探针/对照。**

## 5. 口径与验证（**必须记账**）

* **测的是构造峰值**（`--no-nucleation --steps 1`）。这在本项目里是合理口径：
  构造期一次性分配全部 `(nv+1,N³)` 场与 `g.pf.Lam [N³,6,6]`（N=160 时单个就 **1125 MB**）。
* **两点拟合、Δnv = 32** ⇒ 斜率很稳（Δ=2.24 GB），**截距的置信度低一些**。
* ⚠ **交叉核对不完全闭合**：把本定律按 `N³` 缩到 N=80（每 nv 8.7 MB、固定 455 MB）
  预测 nv=276 ⇒ 2.8 GB，而此前记录的 N=80 实测约 5.3 GB。
  ⇒ 说明固定项里有**不随 N³ 缩放**的成分，或那个 5.3 GB 是**步进期峰值**（含弹性求解在飞）。
  **⇒ 因此：正式长跑前，建议在目标构型（N=160、nv=69）上再做一次确证探针。**
* ⚠ **量具陷阱（本轮踩到并留档）**：第一次探针因 `--nuc-init 0` 不在 `_t5_short.py`
  透传列表里而**参数报错、根本没构造**，`time -v` 照样报了 `14 MB / 0.24 s` ——
  **一个看起来像测量结果的假数**。判据：**RSS < 200 MB ⇒ 没构造 ⇒ 该点作废**。
  已在 `_t5_nvprobe160b.sh` 里写成硬检查。
