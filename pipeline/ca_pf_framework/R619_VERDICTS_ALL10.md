## ②-1 C-5 违反 —— 真，但 banner 用错步数轴

**判据算术（核对通过）**
```
beta_h_min(20000, dx=62.5 nm, t=510 nm, δ=0.3) = 7.1111
```
与 banner 自报的 `7.111` **精确一致** ⇒ 判据实现无误。
δ 敏感性：`beta_h_min(..., δ=0.1) − beta_h_min(..., δ=0.3) = 1.098612 = ln 3` ✅（PASS）。

**banner 错在哪**
`N_steps` 取的是 CLI 的 `--steps 20000`。但本算例生效 `qs_clock=1`：
* `:2343-2365` 档内 `T` **不动**，收敛后才降一档；
* 真实步数上界 = `qs_max_relax(100) × 档数`；
* 档数 = `floor(α_KM·(M_s − T_end))`，而**生效 `alpha_km = 0.041739`**（不是框架参考值 0.011）
  ⇒ 档数 = **23** ⇒ 上界 **2300 步**；
* `beta_h_min(2300, 62.5 nm, 510 nm) = 4.948 < 6.477` ⇒ **在该口径下 C-5 不违反**。

⇒ **同一条判据，步数轴从 20000 换成 2300，结论从"违反 0.63"翻转成"余量 1.53"。**

**后果是否真如所报？** banner 说「板条会增厚 ≈ e^{0.63}×」。
但该算例 **卡在 step 1**（R617）、`V0=Vt=2.495e-19` m³ ⇒ **那些步数一步都没走**
⇒ 增厚**未发生**。

**判定**：判据**真**（数值口径需修），banner 的**因果断言在该算例上未兑现**。
修法方向（不预先钉死）：让 `beta_h_min` 的调用取**该算例真实生效的步数轴**
（`qs_clock` 时用 `qs_max_relax × 档数`）。

**运行期数据（`dry_t10B9/meta.json`）**

## ②-4 S14/N2 线性降温占位 —— 真缺口，本配置下惰性

`windowB_km.py:138 linear_cool` 的 docstring **自称占位**。
`_bk_exp.py:2343-2355`（读全）：

```python
if _qs_clock:
    if _qs_conv and not _qs_stop:
        _qs_T -= _qs_dT                      # 只有收敛才降一档
        g.set_T(_qs_T)                       # 档内 T 不动
        g.t = (_qs_T - _Tstart) / (-_q)      # 只把 T 反推成物理时刻
```

⇒ **档内 `T` 是常数**；档序列由 `T_k = M_s − k/α_KM` 定义、由 `α_KM` 定，**与 `q` 无关**
（只有 `qs_dT` 自动值 `1/α_KM` 用了它）。
⇒ 线性降温**不参与空间演进路径**，只决定：
  (a) `t_sim = ΔT/q`（物理时间轴，本算例 1.5277 ms）；
  (b) 档内伪时间步 `dt' = 0.15dx/(M·ΔG(T_k))` —— 与 `q` 无关。

**判定**：真缺口（真实 LPBF 是反复热循环，`windowB_km` 里已有
`from_cooling_rate`/`lpbf_like` 可选路径），但**在本配置下对微观组织完全惰性**。
⇒ 按「改动最小」原则：**只记账，不改代码**（除非用户要求把 `therm_hist` 改成 `lpbf`）。

## ②-9 两轴来源不同 —— 真问题（量化）

生效值（`meta.json`）：
```
w_ax  = [0.7071067811865475, 0.7071067811865476, 5.596961321313178e-17]
        ⇒ 与 (1,1,0) 的 max|cos| = 1.00000000 ⇒ 就是 {110} 型方向（= 晶体学 {011}）
```

* `|w_ax · n_hab| = 0.000023` ⇒ **夹角 89.999°**（二者**近乎正交**）；

而 `npref` 是弹性的 ⇒ **混用是否可接受**。

## ②-10 `mob` 差 10⁴ —— **否**（出处表量纲笔误）

**引擎量纲（代码级双证）**
* `windowB_drag.py:7`：`v = M_GB[ΔG − P_drag(v)]` ⇒ `[M] = (m/s)/(J/m³) = m³/(J·s)`；
* `windowB_drag.py:48`：`v_linear(dG, M) = M·ΔG` 同证；
* `windowB_surface.py:5351`：`dt = cfl·dx/(M·dmax)` ⇒ 同上（否则不是时间）；
* `windowB_surface.py:593`：`self.M = Mob  # 含 Ω（记账：M 已含摩尔体积）`。

**而出处表 `windowB_closure.py:753` 把它标成 `m⁴/(J·s)`** ⇒ **笔误**。

**量级对照（换算后）**

| 源 | 原值 | 量纲 | 换算 `m³/(J·s)` | 与引擎 `1e-9` 之比 |
|---|---|---|---|---|
| Salama 2024（原文参数表已核） | `1×10⁻¹³` | `m⁴/(J·s)` | `÷Ω_V(1.064e-5 m³/mol)` = **9.4e-9** | 引擎大 **~106×** |
| Boccardo et al. 2024（`arXiv:2404.09806`，Ti-64 体相场，附录 A.2 引 Ref.[102]） | `0.00125·e^{−9500/T}` | `m³/(J·s)` | 800 K **8.8e-7** / 1200 K **4.6e-4** | 引擎小 **~880×** |
| 引擎生效 | `1e-9` | `m³/(J·s)` | `1e-9` | — |

⇒ **两个独立文献值彼此差约 2 个数量级，引擎夹在中间**。
⇒ 「引擎比真实小 10⁴ 倍」这句话（`_bk_exp.py:2049` 的注释）**与文献不符，撤回**。
⇒ 真结论：**该值没有任何本体系锚点**（出处表 `[标]`）⇒ 进 ③ 的待补清单。
