## §1 ★ 内存账：`R550` 的定律**低报 2.6–4 倍**（必须换掉）

**新实测**（`_r581_memfit.py`，独立看门狗读 `/proc/<pid>/status` 的 `VmHWM`）：

| N | nv | **实测峰值** | R550/R580 两项定律 | 旧/实 |
|---|---|---|---|---|
| 160 | 24 | **5087.9 MB** | 1984.4 MB | 0.39× |
| 160 | 72 | **8606.3 MB** | 2921.9 MB | 0.34× |
| 64 | 24 | 513.5 MB | 127.0 MB | 0.25× |
| 64 | 540 | 3100.3 MB | 772.0 MB | 0.25× |

**根因（口径不同，不是谁算错）**：旧定律拟合的是**常驻数组**；而 **OOM 看的是 `VmHWM` 峰值**
（含全部临时量）。判据必须取峰值。

**三项拟合** `M = a·(nv·CELL) + c·CELL + d`（最大相对残差 2.4%）：
`a ≈ 19.2–19.9`、`c ≈ 96–800`、`d ≈ 205–382 MB`（N=64 与 N=160 系列各一套）。

**⇒ goal §(12) 里写的「`onfly+f32` ⇒ `a=5.000` ⇒ nv=540 需 11.8 GB」这一条要改成：
按峰值口径 `a≈19`，`nv=540` 需 41.8–42.7 GB ⇒ 不可行。**

## §2 ★ 时间账：步数前提**已被现场取证推翻**

`R492_INTEG_AND_BUDGET.md §3` 用的是 **9200 步**。`R525 §9.1` 已实测「准静态钟自己停在
`T_end` ⇒ ~600 步」。**本轮两个长跑现场再次确认**（`_w2_r581_p2_p2_b*.log`）：
```
[qs] 档 4 收敛：T=509.36 K  用了 100 步  窗口 Σ|ΔV|/V=0.0132  dG_max/dG_ref=1.09
```
⇒ 每档 ~100 步 × 档数 ⇒ **几百步量级**，不是 9200。

**新实测的时间标度**（`_r581_nvscale.py`，同一会话）：
* `s/步 ≈ 3.2085e-2 · nv^0.721`（N=64）⇒ **次线性**
* N 64→160 是 **17.23×（nv=24）/ 17.60×（nv=72）** ⇒ 差 2.1% ⇒ **近似可分离**
* **N=160 / nv=48 实测 10.09 s/步、峰值 7.42 GB、0 Traceback⇒ 600 步 ≈ 1.7 h**
* 若硬按 nv=540：**51.1 s/步 ⇒ 600 步 ≈ 8.5 h**（但内存先撞墙，见 §1）
