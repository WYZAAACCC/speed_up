# R506 —— 任务(5) 的参数闭环：`α_KM` 与「块厚」不自洽（**新查出的参数缺陷**）

> 2026-10-01 ｜ 依据：`R502_BLOCKCOUNT.md`（块数口径）、`windowB_closure` 的文献带
>
> **结论一句话**：**所有归档 A/B 臂用的 `α_KM = 0.041739` 使块厚 **12.2 µm**，
> 超出框架自己登记的文献带 `(1.0, 6.0) µm` 两倍**；
> 换成**框架自己的参考值 `α_KM = 0.011`** ⇒ 块厚 **3.23 µm** 落在带内，
> **且同时满足 C5 的总根数、块数几何上界、内存** ⇒ **任务(5) 的参数闭环在这里。**

---

## §1 怎么查出来的

上一轮打通"块数"口径（`--nuc-block-target`）之后，自然要问：
**每块几根、块数几个、盒子多大**才自洽。把**五个约束**放在一起解（`_r506_paramclosure.py`）：

| # | 约束 | 出处 |
|---|---|---|
| **①** | **块厚** `W_block = n·t ∈ (1.0, 6.0) µm` | `windowB_closure.W_BLOCK_BAND_UM`（文献带） |
| **②** | **每块根数** `n = α_KM·(M_s − T_end)` | C-2（`alpha_km_n_lath`） |
| **③** | **块数几何上界** `B ≤ L_box²/(plate_L·plate_W)` | `R502_BLOCKCOUNT.md`（本轮新增） |
| **④** | **C5 总根数** `B·n ∈ 220–450` | `NEXT_TASKS_FOR_REVIEW.md §4.1` |
| **⑤** | **内存** `(B·n+1)·N³·w ≤ 22 GB` | `R502 §3` |

**自检全过**：T1（框架函数 vs 手算，相对差 0）、**T2 负对照**（归档值必须超带 —— 确实超了）、
T3（文献带取自框架、不写死）。

## §2 主表（`t = 510 nm`、`plate_L×plate_W = 1000×500 nm`、`T_end = 298 K`）

| `α_KM` | `n`/块 | **块厚** | ①带内? | C5 需 `B` | ③`B≤B_max`(10 µm) | ⑤内存(f32) |
|---|---:|---:|:--:|---:|:--:|---:|
| 0.005 | 2.9 | 1.47 µm | ✅ | 77–157 | ✅ | 6.9 GB ✅ |

## §3 ★ 两条结论

### 3.1 ❌ **`α_KM = 0.041739` 与「块厚文献带」不自洽**（新查出）

* `windowB_km.py:348-349`：`ALPHA_KM_BAND = (5.0e-3, 1.1e-2, 2.0e-2)`、`ALPHA_KM_REF = 1.1e-2`
  —— 都标着 `[A] 占位`（文献常见量级 1e-2）。
* **归档 A/B 臂用的是 `0.041739`** ⇒ **参考值的 3.8 倍、带上沿的 2.1 倍**。
* ⇒ 推出 `n = 24 根/块` ⇒ **块厚 12.24 µm**，而框架自己登记的文献带是 **1–6 µm**。

**⇒ 这是**新的**一处"参数不闭环"**（此前只登记过 `α_KM` 是 `[标]`，没算过它的**后果**）。

### 3.2 ✅ **换成框架参考值 `α_KM = 0.011` ⇒ 五个约束同时成立**

```
α_KM = 0.011  ⇒  n = 6.3 根/块  ⇒  块厚 3.23 µm ∈ (1.0, 6.0) ✅
C5 要 220–450 根 ⇒ B = 35–71 个块  ≤ B_max = 200 ✅
N = 160（10 µm）、f32 ⇒ 内存 6.9 GB ≤ 22 GB ✅
```

**⇒ ⇒ 任务(5) 的目标配置确定了：**

| 项 | 值 |
|---|---|
| `--alpha-km` | **0.011**（框架参考，不是归档的 0.041739） |
| `--nuc-block-target` | **≈ 50**（35–71 之间；50 块 × 6.3 ≈ 315 根） |
| `--nuc-fresh-every` | **≈ 6**（= `n(T_end)`，每 6 个事件建 1 个新块） |
| 盒子 | **N=160 / Δx=62.5 nm ⇒ 10 µm** |
| dtype | **f32**（f64 会到 13.9 GB，偏紧） |
| 内存 | **≈ 5.2 GB**（315 根） |
| `--nthreads` | **10–16**（`R488`：2.52×） |
| `--qs-clock 1 --nuc-supercrit 1 --nuc-sites-refill 1` | 三个新开关全开（集成已验，`R492`） |
| `--T-end` | **298 K** |

## §4 ⚠⚠ 必须随任何结论一起报的记账

**换 `α_KM` 会改掉全部归档 A/B 的物理** ⇒ 影响面必须说清：

| 结论类型 | 是否受影响 |
|---|---|
| **"板条有几根 / 块有多厚"** 类**定量**结论 | ❌ **作废**（`n` 从 24 变 6.3，差 3.8 倍） |
| **"块结构会形成 / F3（低角晶界）会出现 / 块间会接触（`nf2`）"** 类**拓扑**结论 | ✅ **仍成立**（它们与根数无关，只与"有没有这些机制"有关） |
| `abA`/`abB`/`_r464` 的**几何量**（`Vt`、`nslab`、长宽比） | ❌ **必须在新参数下重测** |
| 任务(1) 的 S1–S13 判定表 | ✅ 不受影响（那些是**机制**层面的判定） |

**⇒ 归档数据一律保留**（F 盘，不删），但**引用时必须带 `α_KM` 口径**。

## §5 还需要你拍板的一件事（**已从三件收敛到一件**）

* **任务(5) 目标**：现在 `10 µm 盒子 + 填满` **可以同时满足**（§3.2 的配置），
  但代价是 **`α_KM` 从 0.041739 改成 0.011** ⇒ **归档 A/B 的定量结论作废、要重跑**。
  * **选项 A（推荐）**：换 `α_KM = 0.011` 重跑——**这是唯一五约束自洽的配置**；
  * **选项 B**：保留 `0.041739`（与归档可比），但**放弃 C5**，接受块厚 12.2 µm（超带）；
  * **选项 C**：保留 `0.041739` 但把 `t` 调小到 `≤ 250 nm` 让块厚回到带内
    （`24 × 250 nm = 6.0 µm`，正好在上沿）——⚠ 但 `t` 是有文献值的（`T_LATH_BAND_NM`），
    **不能为了凑带而改**。
* ~~GPU 甲/乙~~：`R489` 已给出判决（算子级 0.24–0.41×；常驻上界 1.49–1.58×），
  **CPU 那一半已白赚 2.52×** ⇒ 建议先只上多核，GPU 等你明确要再做端到端 A/B。
* ~~温度档 ΔT~~：`R477` 的默认 `ΔT = 1/α_KM` **有 athermal 律依据**（复现 C-2 的 `T_k`）
  ⇒ **建议就用它**；取粗只会把 burst 强度变成"建模选择"。
