# R579 —— 并行编排 + goal §(5)(6)(7)(9) 的实测结论

> 本轮的关键变化：**不再一次只跑一道**。20 逻辑核、22.9 GB 可用，
> 而此前单道作业只用 1–5 核（λ 建表是**单线程**的）⇒ 机器长期只用了 ~25%。
> `_r579_par.sh` 把互不依赖的作业用 `taskset` 绑到**互不相交**的核上同时跑。

## §0 并行编排：为什么判据仍然有效

* 本项目**有效**的性能判据都是**同一个作业内部的配对比值**（交错 A/B）；
  绝对墙钟早已记为"跨会话不可比"（`AGENTS.md §7.5 P1`）。
* ⇒ 只要同一作业的两臂绑在**同一组核**上，比值有效；作业之间只需**互不重叠**。
* 核分配（`_r579_par.sh`）：

| 道 | 核 | 作业 |
|---|---|---|
| T | 0-5 | goal §(3) 六臂轮换 A/B（计时） |
| MA | 6-9 | N=160 内存清单 f64/nv=4 → f32/nv=4 |
| MB | 10-13 | N=160 内存清单 f64/nv=8 → f32/nv=8 |
| G | 14-15 | goal §(9) GPU 处置 |
| P | 16-17 | goal §(7) 两个单变量实验 |
| R | 18-19 | 归档路径**逐位回归** |
| N | 14-15（G 完成后） | N=160 墙钟/峰值内存标度 |

* **内存道为什么两波**：每个 N=160 构型峰值 3–4 GB（`Lam` 1.18 GB + `lambda_packed` 临时量）；
  4 个一起 ≈16 GB，加上其它道会逼近 WSL 的 23 GB ⇒ 有 swap 抖动 / 整机卡死风险
  （`AGENTS.md §3.12` 记过 WSL 因内存压力整体无响应）。⇒ 两波，峰值 ~8 GB。
* 编排器带 **60 s 内存看门狗**，实测全程 avail ≥ 18.7 GB。

## §1 ★ goal §(9) GPU：**v1 的"关闭"判决是量具错**，已推翻

### §1.1 v1（`_r579_gpu.py`）

| 项 | 实测 |
|---|---|
| GPU 常驻 σ 链加速比 | **5.645×** |
| 正确性 | 2.225e-16 ✅（判据 ≤1e-5） |
| 负对照（Λ 取负） | 2.000e+00 ✅ |
| "一次性上传" 120 MB | 0.4709 s ⇒ **0.25 GB/s** |
| ⇒ 判决 | 按预登记"搬运占比 > 70%" ⇒ **CLOSED** |

### §1.2 为什么 0.25 GB/s 不可信，以及重测（`_r579_gpu2.py`）

那一次 `cp.asarray` **混了 CUDA 上下文初始化 + 首次显存分配**，是**冷启动**数字。
重测（warm-up 后重复取最小）：

| 项 | 值 | 比值 |
|---|---|---|
| 冷启动 H2D（48 MB `pf.phi`） | 0.3436 s ⇒ **0.136 GB/s** | 1× |
| **稳态 H2D** | 0.0373 s ⇒ **1.26 GB/s** | **9.2×** |
| **稳态 D2H** | 0.0360 s ⇒ **1.30 GB/s** | 9.5× |
| 常驻 σ 链 | CPU 0.1157 s ｜ GPU 0.0173 s ⇒ **6.685×** | |

**混合路（水平集在 CPU、弹性在 GPU）的每步账**：
上行 `phi` 48 MB = 0.0373 s；下行 `edk/edl` 4 MB = 0.0030 s ⇒ 每步搬 **0.0403 s**；
弹性链省下 **0.0984 s** ⇒ **净收益 +0.0580 s/步**，搬运占比 **70.0%**。

### §1.3 修正后的判决

| 分支 | 判据 | 结果 |
|---|---|---|
| **A 全驻留移植** | 每步搬运 = 0 ⇒ 只看加速比 ≥1.3× | **6.685×** ⇒ 不触发关闭 |
| **B 混合** | 净收益 > 0 且搬运占比 ≤70% | **+0.0580 s/步、70.0%** ⇒ 不触发关闭（**贴边**） |

⇒ **GPU 这条线不能按"搬运占比"关闭**（该指标的 v1 取值已被证伪）。
转为**"待做真移植"**，判据写死为：
1. 全驻留移植后**整步**加速比 ≥ 1.3×（不是只看 σ 链）；
2. 若走混合路：每步净收益 > 0 **且** 搬运占比 ≤ 70%。

⚠ **本轮不做移植**（工作量远超一轮），只把量具修正并登记。
⚠ 这是本项目第三次在 GPU 这条线上出**量具错**（前两次：`B'` 的异步计时 1200× 假象、
算子级 0.406×/0.239× 的"更慢"），**每次都值一条纪律**：
**GPU 的数必须 (a) 含同步 (b) warm-up 后取稳态 (c) 报搬运**。

### §2.3 C5 判定（用**实测** `a`/`c`，**无外推**）

预算 22 GiB = 22528 MB；N=160 需要 nv ≈ 781（当前几何）。

| 配置 | `a`(B/胞) | 固定(MB) | **nv_max** | 可达分数 | 够 781 吗 |
|---|---|---|---|---|---|
| 现状（物化 + f64 φ） | **16.000**（实测） | 1343.8 | **338** | 13.0% | ❌ 差 **2.31×** |

⇒ **结论：C5（10 µm 盒填 30%）在当前配置下不可行；唯一可行的组合是

  ⇒ **两个开关必须同时开**。

> ⚠ **对归档结论的更正**：`R550 §6` 的"f32 ⇒ nv_max 605→1089 ⇒ C5 基本可达"是用

> `_bk_exp.py` 不覆盖）⇒ 那两行**不能引用**。本轮给出的是 N=160 实测值。

## §3 goal §(4)①：`pf.phi` 的**全部调用点审计**

`grep -n 'pf\.phi' *.py`（173 处命中，剔掉测试/探针后**生产引擎里只有下面这些**）：

| 位置 | 角色 | 说明 |
|---|---|---|
| `windowB_surface.py:3423` | **写** | `soft=False` 分支：`self.pf.phi[v] = (reg == v+1)`（hard 指示场） |
| `windowB_surface.py:3470-3476` | **写** | `soft=True` 分支：`pf.phi` 若是 bool 先 `astype(float64)`（**+7 B/胞**），再逐 v 写 `0.5(1−tanh(φ_{v+1}/w))` |
| `windowB_pf3d.py:eps0_fields()` | **读** | `np.einsum('vp,v...->p...', self.e0v, self.phi)`（或 loop/gemm） |
| `windowB_pf3d.py:eps0_fields_idx()` | 读 | 不读 `self.phi`，走 `idx` gather（另一条路） |
| `windowB_pf3d.py:_epsh()/_epsh_r()` | 经上二者 | 供 `sigma_tensor()` 与 `E_el()` |
| `windowB_pf3d.py:E_chem_grad()` | 读 | **诊断路径**，不在每步热路径 |
| `windowB_pf3d.py:step()` | 读 | 弥散界面 PF 的老路径，**level-set 生产不走它** |
| `windowB_surface.py:122/124` | 写 | 模块级辅助函数里的初始化 |

**⇒ 结论（goal §4① 的第一问）**：生产路径上 `pf.phi` 的**唯一实质消费者是 `eps0_fields()`**。
⇒ "不物化"是可行的，但**必须小心两件事**：
1. **峰值 vs 常驻**：若在 `eps0_fields()` 里临时造一个 `(nv,N³)` 的 `h`，**常驻降了、峰值没降**
   ⇒ 对 C5 的内存墙**没有帮助**。必须**按 v 分块**累积进一个 `(N,N,N)` 的 scratch
   （分块大小是新的可调参数，要单独记账）。
2. `E_el()` / `E_chem_grad()` / `step()` 都读 `self.phi` ⇒ 不物化后要给它们一条路径
   （诊断路径可以按需现算，代价可接受）。

⇒ 实现留到下一轮（要做成开关 + 逐位对照 + **双轴判据**：速度与内存都要报）。

## §4 goal §(6)：`par.gradient` 的边界公式复刻（已完成）

`windowB_par._np_gradient_edge2(f, dx)` —— **逐行照抄** numpy 2.5.3
`lib/_function_base_impl.py` 的 `edge_order=2` 分支（含**运算次序**）：

```python
a = -1.5 / ax_dx ; b = 2. / ax_dx ; c = -0.5 / ax_dx
out[0] = a * f[0] + b * f[1] + c * f[2]
```
**不是** `(-1.5 f0 + 2 f1 − 0.5 f2)/dx` —— 两者舍入路径不同。

⇒ **真实墙钟收益 ≈1.8%，正好落在 run-to-run 噪声（min–max 散布 ~7%）之下**。
**这是 `AGENTS §7.5 P4/P14` 的第三次实例：并发占比 ≠ 墙钟收益。**

—— 它仍然是一条**该保留的**优化（逐位相同、计数下降、任何一次测量都没有显著变慢），
但**不能拿它当提速卖点**。
