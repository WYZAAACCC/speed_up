## 零、架构（2026-09-18 用户确认）—— 两条轨道 × 两个阶段

**这是本项目的顶层架构，之后所有工作都挂在它下面。**

### 0.1 两条轨道

把**拓扑变化**与**晶界上溶质的变化**拆成两条独立轨道，各自演进、互相提供下一步所需的数据：

```
拓扑轨道 T:   T_n ──[传统相场 或 神经网络]──▶ T_{n+1}
溶质轨道 C:   C_n ──[神经网络(逐面算子) 或 传统求解器]──▶ C_{n+1}
```

**耦合是离散、交错的**（不是同时求解）：

```
上一步的拓扑结果  ──▶ 影响这一步的溶质变化     C_{n+1} = F_C(T_{n+1}, C_n)
这一步的溶质变化  ──▶ 影响下一步的拓扑变化     T_{n+2} = F_T(T_{n+1}, C_{n+1})
```

### 0.2 两条轨道贯穿两个阶段 ⇒ 2×2

| | **阶段 1**（熔化→凝固） | **阶段 2**（粗化与偏析） |
|---|---|---|
| **拓扑轨道** | 形核 + 外延生长 + 竞争生长 | 粗化（晶粒长大/消失） |
| **溶质轨道** | 凝固前沿的偏析 | 晶界偏析与扩散 |

**每一个格子都可以独立选择"传统求解器"或"神经网络"。**

### 0.3 拆分带来的收益

1. **可替换性**：每条轨道独立选求解方式——贵的用 NN，需要保证精度的用传统求解器
2. **可学习性**：**拓扑变化并非不能学**。之前认为"难学"是因为它与溶质耦在一起、输入输出不干净；
   拆开之后它变成"晶粒网络 → 新晶粒网络"的映射，输入输出明确，**可以训练神经网络**
3. **误差隔离**：尺度分离问题（C4）只存在于**溶质轨道**，不污染拓扑结果
4. **可归因**：两条轨道可分别对真值验证，而不是耦在一起无法定位

### 0.4 【新增工作项 C8】实现真实的溶质→拓扑反馈

**用户要求：「真实溶质对拓扑的反馈是怎样的就怎样反馈」。**

**现状：当前模型没有反馈。** `f_loc` 只进入 c 方程（`SplitCHParsed`），
**不进入 η 方程**（η 用 `barrier_mu` 的 `mu` 与 `kappa_op`）。
⇒ 变分不一致，**溶质拖曳（solute drag）完全缺失**。

**这不是疏漏，是一个有记录、被主动推迟的项**——`stage1_meltpool_c.i` 的注释原文：
> 「若被 ACGBPoly 复用，耦合强度会随温度变号 —— 不是我们要的。所以这里
> **只在 c 方程里体现分凝，η 方程不反向耦合**。代价：**暂时没有溶质拖曳。等这一版跑通再加。**」

**补法（原则）**：让自由能成为**单一泛函**，η 与 c 都从同一个 `f` 变分而来。
把自由能拆成两部分：
```
f = f_phase(η)  +  f_solute(c, η)
     ↑ 晶粒结构 + 熔化开关        ↑ k_c/2(c−c0)² + A_part·c²·g(η)
```
- η 方程：`ACGrGrPoly`（现有的晶粒结构 + 熔化开关）**加上** `ACBulk(f_name = f_solute)`
- c 方程：`SplitCHParsed(f_name = f_solute)`（不变）

**这样溶质拖曳会自然涌现**：晶界是溶质的低能位点（`g(η)` 在晶界处 < 1），
晶界迁移必须重新分配溶质 ⇒ 阻力。**且不需要额外写拖曳项**——变分一致就自动有了。

**待验证**：
1. 加上 `ACBulk` 后**晶粒动力学不能被破坏**（收敛性、2a/2b 验证）
2. 要有一个**受控实验证明拖曳存在**：同一晶界、不同溶质浓度/扩散系数下，
   比较迁移速度——溶质浓度高、扩散慢时应显著变慢
3. 温度变号问题（旧注释提到的）需重新评估：`f_solute` 里没有熔化开关，
   `g(η)` 在液相自动为 0，**预计不会变号**，但必须实测确认

### 0.5 与阶段 A/B 已完成工作的关系

阶段 A（正确性与收敛性）与阶段 B（性能）的结论**继续有效**：
- 非 AD 版二次收敛到 4e-10、`nl_abs_tol ≤ 1e-9`、起始 `dt = 1e-7`
- 生产求解器 = **MPI n=8 + ASM**（全尺寸下比 MUMPS 快 4 倍、内存一半）

但 **C8（反馈）与 C4（截留）都会改变物理，会牵动 C1/C2 的验证**，
所以 **数据生成仍必须放在阶段 C 全部完成之后**。

### 2.3 【新发现，2026-09-18】解对求解精度有敏感依赖

**实验**：同一算例（215×75，非 AD），A = MUMPS+`nl_abs_tol=1e-9`，
B = ASM+`nl_abs_tol=1e-6`。**t=0 时两解逐位相同**（已验证 `max|Δ|=0`）。

**结果 —— 两解发散，不是收敛：**

| t | gr0 的 relL2 | gr4 | c | w |
|---|---|---|---|---|
| 5.0e-07 | 3.4e-09 | 1.1e-04 | 1.6e-07 | 6.8e-05 |
| 1.0e-06 | 6.3e-06 | 6.2e-04 | 2.1e-06 | 1.4e-03 |
| 1.75e-06 | 1.8e-05 | 5.4e-04 | 4.2e-06 | 1.0e-03 |
| 2.875e-06 | **1.5e-03** | **1.8e-03** | 6.7e-05 | **2.1e-02** |

**最后一步跳了 100 倍。**（`max|Δ|` 被界面单元主导，判趋势要看 relL2；
`unique_grains` 的差值是 GrainTracker 的**整数标号**，不是物理量，已从统计中剔除。）

**两种解释，必须分辨：**

| 解释 | 含义 | 判别实验 |
|---|---|---|
| **(a) ASM 线性解不准** → B 的解本身是错的，误差被放大 | 工程问题：**生产必须用 MUMPS** | 跑 **C = MUMPS+`1e-6`**（与 B 同容差、与 A 同求解器）。C≈A 且 C≠B → 是求解器 |
| **(b) 系统对精度真敏感**（拓扑事件附近的混沌式放大） | **科学问题**：长时间后"真值"不唯一，神算子的训练目标本身不 well-defined | C 与 A、B 都不同 → 是敏感依赖 |

**判别结果（2026-09-18，已定论）——两个假设都不对，真因是容差：**

| 对比 | 变的是什么 | `gr0` 的 relL2（t=1.089e-05） |
|---|---|---|
| **C vs B** | **只换求解器**（同容差 1e-6） | **2.61e-13** ← 机器精度级 |
| **A vs C** | **只换容差**（同求解器 MUMPS） | **2.08e-03** |
| A vs B | 都不同 | 2.08e-03 |

**结论：**
1. **同容差下 ASM 与精确 LU(MUMPS) 给出同一个解**（2.6e-13）。**ASM 并不"不准"**，
   它解的是同一个方程、同一个答案。先前"ASM 线性解不准"的读法是**错的**。
2. **发散 100% 来自残差容差**，与求解器无关。
3. **真正的问题：`|R|=1e-6` 对应约 `2e-3` 的溶液相对误差。**
   → **残差容差是本问题解精度的坏代理**（条件数高）。这是必须记住的一条。
   → 生成训练数据**必须用紧容差**（≤1e-9），否则"真值"只在 2e-3 精度上成立。

**决定性确认（D = ASM+`nl_abs_tol=1e-9`，已跑完）**：

| 对比 | 容差 | 只变什么 | `gr0` relL2（t=4e-5） | 随时间增长？ |
|---|---|---|---|---|
| C vs B | 1e-6 | 求解器 | **1.4e-13** | 否 |
| **A vs D** | **1e-9** | 求解器 | **~1e-15** | **否** |
| A vs C | — | 容差（同 MUMPS） | 2.1e-03 | 是 |

**⇒ 在任意给定容差下，ASM 与精确 LU 给出同一个解，且差异不累积。**
**⇒ 求解器选择与精度无关；唯一决定精度的是容差。**

### 2.4 生产配置结论（阶段 A 的出口）

**必须用 `nl_abs_tol ≤ 1e-9`**，否则训练数据的"真值"只在 `2e-3` 精度上成立。

求解器按速度选（**注意：下面的耗时数据被并发作业污染，只能作参考，需在空闲机器上重测**）：

| 配置 | 215×75 耗时 | 解的质量 |
|---|---|---|
| MUMPS + 1e-9 | 955 s | 基准（精确） |
| ASM + 1e-9 | 1522 s | 与 MUMPS 差 1e-15 |
| ASM + 1e-6 | 672 s | **与基准差 2e-3** ← 不可用于生产 |
| MUMPS + 1e-6 | 1950 s* | **与基准差 2e-3** ← 不可用于生产 |

\* C 是在并发作业下跑的，耗时不可比。

**倾向**：紧容差下 ASM 的弱预条件子需要远多于 MUMPS 的线性迭代，
所以 **MUMPS + `1e-9` 很可能是最优组合**，但**必须在空闲机器上重测确认**（新增 A8）。

**一个重要的先验怀疑**：215×75 的 `dx=2e-6` 而 `int_width=4e-6` → **界面只跨 2 个单元**，
界面严重欠分辨。**欠分辨界面正是解对网格与求解器最敏感的地方。**
所以这个发散**有可能是粗网格的产物**，在生产的 430×150（界面跨 4 单元）上会弱得多。
**这条必须在全尺寸网格上复测**（新增工作项 A7）。

### 2.5 重要修正：推翻了一个错误归因

**旧的错误结论**（曾写入记忆）："非 AD 版因雅可比不完备，牛顿残差卡在 7.3e-07 地板，
只能把 `nl_abs_tol` 放宽到 1e-6 换取可运行性。"

**实测推翻**：非 AD + **MUMPS（精确 LU）** 二次收敛到 **4.01e-10**，地板根本不存在。
→ **那个 7.3e-07 "地板"是 ASM/ILU 预条件子没把线性系统解准造成的，不是雅可比缺陷。**
这个修正很重要：它意味着**非 AD 不需要"将就"**，配上好的线性求解器就是完整精度的。

### 3.1 关键架构冲突：取向绑在"序参量"还是"晶粒"上

**这是目前最重要的架构决策，它决定形核能否做对。**

MOOSE 的多晶形核正规机制（已核实源码 + 官方文档 `Nucleation/DiscreteNucleation.md`）：

- `GrainTracker` 有 **`reserve_op = N`** 参数 → 保留**编号最后 N 个**序参量为"暂存位"
  （源码 `GrainTrackerInterface.C:30`；`_reserve_op_index = _n_vars - _n_reserve_ops`）
- 在暂存位（如 gr7）上挂 **`DiscreteNucleationForce` + `Reaction`**，inserter 设 **`hold_time = 0`**
- 形核时暂存位被点亮 → 下一步 `GrainTracker` 检测到新 feature → 分配新晶粒 ID →
  **`remap_grains` 把它重映射到一个正常演化的序参量上** → 暂存位清空待用

**好消息**：不需要预留空闲序参量，`op_num` 不必因形核而增加。

**坏消息（本算例的致命点）**：remap 会把新晶粒从 gr7 挪到（比如）gr2。
而本算例里 **θ_i 硬编码绑定在序参量上**（θ 表展开在 `orient_cos`/`orient_sin`/`L2a`/`align4`
的解析式里，见 §三 约束表）。**remap 一次，该晶粒的晶体学取向就被改掉了** —— 物理错误。
同理，11 个柱状种子挤在 8 个序参量上时，共用序参量的两个晶粒被 2b 当成同一取向。

**三条出路（已用源码逐行核实，2026-09-18）：**

#### ❌ 方案 (c) `GBAnisotropy` —— **确认不可用**，三个独立死结

1. **`mu` 属性名硬编码**（`GBAnisotropyBase.C:53,171`）→ 与 `barrier_mu` 同名双声明，
   默认 `material_dependency_check=true` 下直接 `mooseError`。
   绕过（关掉该检查）也没用，因为：
2. **它算不出本算例的物理**：σ 是逐对**常数表**（`GBAnisotropyBase.C:100`，
   `_sigma[m][n]` 全程不变）—— **无法表达 Read-Shockley**；L 只有 `exp(-Q/kbT)` 与逐对常数
   `_mob[m][n]` —— **完全没有 2b 的热梯度对齐**（整个文件没有 `grad_T`/`align`）；
   `mu` 与 (a\*,γ\*) 强耦合（`GBAnisotropy.C:62-63` 用 `6*σ_init/w`，σ_init=(max+min)/2）
   不能外改 —— 这一点 [[d-version-stall-debug]] 已用数值实验证明过。
3. **不提供任何导数属性** → `ACInterface` 在构造函数里**无条件**索取
   `dL/dop`、`d2L/dop2`、`dkappa_op/dop`（`ACInterface.C:34-36,53-61`），
   拿不到时 `MaterialData.h:398-405` 会**静默填零**，不报错 ⇒ **残差对、雅可比错**。

#### ✅ 方案 (b) 迁移 per-grain 取向 —— **机制在 MOOSE 里已现成**

**关键认识：remap-safe 这件事 MOOSE 已经解决了。** 原因有三层：
1. 晶粒 ID **单调、永不复用**（`GrainTracker.C:1786-1798` `getNextUniqueID()`）
2. remap 只改"晶粒占哪个序参量"，**不改晶粒 ID**
3. `EulerAngleProvider` **按晶粒 ID 索引**，而 `OutputEulerAngles` 在求值时把当前单元
   解析成晶粒 ID 再查表（`OutputEulerAngles.C:38-54`）

**缺的只是"从 per-grain 欧拉角算 σ/L 的材料"这一个部件**（全 MOOSE 没有这个材料）。
现成可参考的写法：`ComputePolycrystalElasticityTensor.C:63-89`（唯一消费 `EulerAngleProvider`
的 Material，用 `getVarToFeatureVector(elem_id)` 逐 op 取 grain_id 再查欧拉角）。

#### 三条具体路径，按代价排序

| 路径 | 做法 | 代价 | 物理保真 |
|---|---|---|---|
| **A（最低，先做）** | `GrainTracker` 加 `reserve_op = N`，把最后 N 个 op 保留为形核专用。保留 op 上的晶粒**永不被 remap**、**永远拿固定 ID**（`GrainTracker.C:1207,1239,1604-1605`）⇒ `op ↔ 晶粒 ID ↔ 取向 θ` 三者恒定 | **改一行输入文件** + 重新生成时固定保留 op 的 θ | **零改动**，`gen_aniso.py` 表达式一字不改 |
| **B（中）** | AuxVariable 桥：`EulerAngleFileReader` 提供取向 + 3 个 `OutputEulerAngles` → `phi1/Phi/phi2` 逐单元 AuxVariable，`L2b`/`align4` 改成耦合它们 | **约 1 天**，只动输入文件 | ⚠ **有损失**：① Read-Shockley 的**逐对** σ(Δθ_mn) 无法重建（只拿得到逐单元 θ，拿不到"第 m 个 op 的 θ"）② `d(align4)/d(gr) ≡ 0` ⇒ 雅可比变差、`L` 在晶界间断，**必须重测收敛性** |
| **C（最高）** | 写 `GrainOrientationGBAnisotropy` Material，照抄 `ComputePolycrystalElasticityTensor` 的 grain_id 查表模式做真正的逐对循环 | **约 250 行 C++ + 重编译**，1–2 周含调试 | **逐位等价于现在的 `aniso_block.i`**，完全 remap-safe |

#### ✅ B0a 已实测澄清：`reserve_op` 是【永久槽位】语义

最小实验（`b0a_nucleation.i` + `b0a_run.sh`，20×20，4 个 op，`reserve_op=1`，
`DiscreteNucleationFromFile` 在 (15,15) 放一个核）：

```
max_gr3:  0 → 1.17   （核出现并稳定留在保留 op 上，**没有被 remap 走**）
n_grains: 2 → 3 → 4 → 3
```

**结论：保留 op 上的晶粒永不被 remap。第二个调研引源码的读法正确，
官方文档"staging order parameter / 会被 remap 出去"的措辞在本版本 MOOSE 上有误导性。**

**对形核设计的直接含义：**
- 每个保留 op 承载 **1 个**形核晶粒，且其取向**固定为该 op 的 θ**
- ⇒ **`op_num` 必须 ≥ 基体晶粒数 + 期望形核次数**
- ⇒ 而这会让 `L2a` 的 O(n²) 成本上升（§三 约束表），两者需要权衡

**⚠ 本实验的两条已知局限**（不要过度外推）：
1. `max_gr3` 稳定在 **1.17 而非 1.0** —— Force+Reaction 本应给出精确的 `u = M(r) ∈ [0,1]`，
   说明还有其他项在起作用，机理未查清
2. 观察到**次要 remap 活动**：t=1.31 时 `max_gr2` 一度到 1.12、晶粒数到 4，之后降回 0.498/3
   —— 说明普通 op 之间确实有 remap。要定论需要更干净的实验（隔离出单次形核）

**→ B0 仍待定（见下），但 A 路径的可行性已确认。**

**已核实的形核 API（可直接照写）：**

```moose
[UserObjects]
  [inserter]
    type = DiscreteNucleationInserter
    hold_time = 0          # 关键：只点亮一步，供 GrainTracker 拾取
    probability = P        # 必填，Material 属性名（形核率密度）
    radius = 2.0           # 默认属性名 'r_crit'；给常数即固定半径
    seed = 12346           # MooseRandom，按 element id 索引 -> 与并行分区无关
  []
  [map]
    type = DiscreteNucleationMap
    int_width = 1          # 核是升余弦圆的盘，不是高斯
    inserter = inserter
  []
  [grain_tracker]
    type = GrainTracker
    reserve_op = 1         # 保留最后 1 个 OP 为暂存位
    remap_grains = true
  []
[]
[Kernels]
  [gr7_force]              # 两个 kernel 组成线性方程 -> 把 gr7 强制设成 map 的仿射变换
    type = DiscreteNucleationForce
    variable = gr7
    map = map
    no_nucleus_value = 0
    nucleus_value = 1
  []
  [gr7_react]
    type = Reaction
    variable = gr7
  []
[]
```

- `DiscreteNucleationForce` 残差：`-((v1-v0)*M(r) + v0)*ψ`，`M(r)∈[0,1]` 是 map 值；**只驱动一个变量**
- 触发是**每 qp 每步按 Poisson 概率随机撒点**，不是判据驱动：
  `rate = probability[qp]*JxW[qp]`，`time_dependent_statistics=true` 时用指数分布精确采样
- **配套 `DiscreteNucleationTimeStep` 后处理**（`p2nucleus` 默认 0.01）喂给
  `IterationAdaptiveDT`，否则单步会同时冒出大量核
- **确定性替代**：`DiscreteNucleationFromFile` 从 CSV 读 `time,x,y[,r]`，完全绕开随机数
  → **做可复现的标定算例时应该用它**
- 另一条互斥路线：`DiscreteNucleation` **材料**（能量罚项 `F=γΣ(c_i-c0_i)²`，走 DerivativeSumMaterial），
  适合守恒序参量；本算例用非守恒的 η，**应走 Force 路线**
- 全仓库**没有** `nucleation_density`、`min/max_nucleation_radius`、`ConservedNucleation` 这些名字
  （`nucleation_radius` 只属于 XFEM 裂纹形核，无关）

| 策略 | 每核效率 | 并发条数（受 21 GB 限制） | 吞吐 |

> **⚠ 修正：求解器从 MUMPS 改为 ASM。**
> 干净复测（同配置、同步数、只差求解器；全尺寸 430×150，3 步 / 14 次牛顿 / 12 次雅可比）：
>
> | | 墙钟 | 线性求解（推算） | 内存峰值 |
> |---|---|---|---|
> | **ASM** | **499 s** | **7.3 s** | **3182 MB** |
> | MUMPS | 2014 s | 114.4 s | 6418 MB |
> | 比值 | **4.0×** | **15.7×** | 2.0× |
>

> 原因已确认是 **MUMPS 的 fill-in 超线性**：内存 486 MB → 6418 MB（13 倍，

> **⇒ 问题越大，MUMPS 越吃亏。生产必须是全尺寸，所以必须用 ASM。**

- **代数化简 `L2a` 的分母**：`Σ_{i<j}(η_i²)(η_j²) = ((Ση_i²)² − Ση_i⁴)/2`，

- 物理型分块预条件子（未试）
- 线程并行（MOOSE `--n-threads`，实测进程只有 2 线程，从未启用）

**⚠ 性能是本项目真正的关键路径，不是物理缺口。**
全尺寸单进程 MUMPS 约 **30 分钟/步** → 165 步 ≈ **80+ 小时/条轨迹**。
要生成几十条训练数据就是几个月。**必须先解决性能，否则没有训练数据。**
候选方向（按预期收益）：
1. **并行 MUMPS（MPI）** —— 直接解并行化，B5 在测
2. **MPI + ASM** —— 每迭代便宜，但迭代数增加
3. **变量 scaling / 步长判据**（B6）—— 可能允许用更松的容差而不损失解精度，直接省牛顿迭代
4. **减小 `L2a` 的 O(n²) 求值成本** —— 每个 qp 都在解释执行上万字符的表达式
5. **移动坐标系 / 局部加密** —— 激光只影响熔池附近，远场演化很慢（但注意 [[grain-solute-acceleration-project]] 已实测 **AMR 会破坏守恒**）

所以 **op_num > 13 时必须走非 AD 路线**（13 → 16 变量 × 4 = 64，正好卡上限）。
既然 A2 很可能指向"非 AD + 好求解器"，这条不构成阻塞，但**必须写进规划**。

### 4.2 C1 详细方案（**已确认可实施**）

**溶质模型的数学形式**（`stage1_meltpool_d.i` 的 `free_energy`）：
```
f_loc = (k_c/2)(c−c0)²  +  A_part·c²·Ση_i²        k_c=0.9, c0=0.35, A_part=0.45
```
平衡时固液两相 `μ = ∂f/∂c` 相等 ⇒ **`k = c_S/c_L = 1/(1 + 2·A_part/k_c)`**

**数值验证通过**（`verify_partition.i` + `verify_partition.sh`，三组变体偏差均 <1%）：

| 变体 | `A_part` | 公式 k | 实测 k | 偏差 |
|---|---|---|---|---|
| A | 0.45 | 0.5000 | 0.5045 | 0.90% |
| B | 0.264 | 0.6303 | 0.6351 | 0.77% |
| C | 0.00918 | 0.9800 | 0.9806 | 0.06% |

**⇒ 改法：`A_part = (k_c/2)·(1/k − 1)`，任意目标 `k` 精确可达。**

**目标值（文献调研结论）：**

| 参数 | 当前占位 | 建议值 | 依据 | 把握 |
|---|---|---|---|---|
| 溶质元素 | 单组元泛指 | **V**（钒） | Ti64 中 V 是主要偏析元素；k_V≈0.63（两个独立来源一致） | ✅ |
| `c0` | 0.35 | **0.036**（V 原子分数，由 4 wt% 换算） | Ti 47.867 / Al 26.982 / V 50.942 | ✅ 纯计算 |
| `k` | 0.5 | **0.63** ⇒ `A_part = 0.264` | Lee 2025 JMRT 36:3796；PanTi CALPHAD | ⚠ 中等 |

**⚠ 已知的模型局限（必须写进论文）**：单组元化丢掉了 Al（k_Al≈0.98，几乎不偏析）。
选 V 是因为它是**主导偏析元素**；Al 的贡献小。**若审稿人要求，升级为双组元**
（c_Al, c_V, w_Al, w_V 四个变量）——代价是每节点多 4 个 DOF，且 `f_loc` 要重写。

**注意 `c0` 与 `k` 必须一起改**：`c0` 是液相名义成分，改了它整条凝固路径都变。

> **重要洞察：模型对 `c` 是尺度不变的。**
> 令 `c → λc, c0 → λc0`（`A_part` 不变），则 `f → λ²f` ⇒ `μ → λμ` ⇒
> CH 方程 `∂c/∂t = ∇·(M∇μ)` 形式完全不变。
> **⇒ `c0` 从 0.35 改到 0.036 是纯粹的"换标签"，动力学一字不变**
> （但让数值有真实物理含义，值得改）。
> **真正的物理变化只有 `k`：0.5 → 0.63。**
> ⇒ 好处：`c0` 那一半不需要重新验证动力学。

> **⚠ 数据作废规则（对整个阶段 C 都适用）**
> 阶段 C 的任何物理改动（`k`、`A_ani`、形核、截留）都会让**此前生成的训练数据全部作废**。
> 且 `feat_spec.py` 的特征 7/11（`c_bulk`）是**绝对量**，会随 `c0` 改变尺度
> （特征 15 的浓度对比是归一化的，不受影响）。
> **⇒ 数据生成必须放在阶段 C 全部完成之后，不能边改物理边产数据。**

### 4.3 C4 详细方案（先测量，再决定）

**MOOSE 有现成部件**（已核实源码）：
```moose
[diff_antitrapping]
  type = AntitrappingCurrent
  variable = c          # 守恒的溶质变量
  v = gr0               # 序参量（每个 op 都要配一个）
  f_name = <前置因子>    # 材料属性
[]
```
残差形式：`F · v̇ · (∇v/|∇v|) · ∇ψ` —— **沿界面法向、正比于界面速度的抗截留通量**。
需与 `CoupledSusceptibilityTimeDerivative`（同 `v`、同 `f_name`）配对使用
（参考 `examples/anisotropic_interfaces/echebarria_iso.i`）。

**⚠ 测量已完成，但第一版设计不足 —— 必须记录这个教训。**

`measure_trapping.sh` 量的是**平衡态** k 随界面分辨率的变化（`w/dx = 1…16`）：

| `w/dx` | 1 | 2 | **4（生产）** | 8 | 16 |
|---|---|---|---|---|---|
| 实测 k | **0.6300** | 0.6303 | **0.6303** | 0.6303 | 0.6303 |
| 偏差 | +0.00% | +0.04% | +0.04% | +0.04% | +0.04% |

**结论一（正面）**：即使界面只跨 **1 个单元**，平衡态分配系数也精确等于 0.63
⇒ **弥散界面在平衡态下没有人为截留，C1 的热力学是对的。**

**结论二（我的设计缺陷）**：抗截留项要解决的是**动态**问题，不是平衡态问题——
平衡态 `V=0`，根本没有边界层，所以**这个测试原理上看不到目标问题**。

**正确的严重性判据是界面 Péclet 数**（薄界面渐近理论要求 `W < D/V`）：
```
W/(D/V) = 4 µm / (5e-9 m²/s ÷ 0.6 m/s) = 4e-6 / 8.3e-9 ≈ 480  ≫ 1
```
**⇒ 模型远离定量区间，抗截留项不是可选项而是必需。**
（这与 C4 的原始判断一致，且给出了定量依据。）

**要做的是动态测量**：移动界面（定向凝固）下量界面处的 `c_S/c_L`，
或直接采用文献的薄界面渐近结果构造抗截留前置因子。

**⇒ 教训：设计验证算例时，先问"这个测试能不能看到目标现象"。**
平衡态测试看不到动态问题，正如分辨率扫描看不到边界层问题。

#### C4 的实施障碍：这是**推导任务**，不是配置改动

MOOSE 的标准实现（`examples/anisotropic_interfaces/echebarria_iso.i`）给出的是
**Karma–Plapp / Echebarria 形式**：
```moose
antitrap_pre = 1/(2*sqrt(2)) * (1 + (1-k) * U)     # 抗截留通量前缀
coupled_pre  = -(1 + (1-k) * U) / 2                 # 配套的时间导数项
```
**但它的变量是无量纲过饱和度 `U = (c−c_l)/(c_l(1−k))`，自由能是稀合金形式
`f = h(φ)f_S + (1−h)f_L`；而本算例用的是原始浓度 `c` 与
`f = k_c/2(c−c0)² + A_part·c²·Ση²`。**

⇒ **前置因子不能照搬，需要针对本算例的自由能形式重新推导薄界面渐近。**

**两条出路：**

| 路线 | 做法 | 代价 |
|---|---|---|
| **(i) 换用标准形式** | 把溶质模型改写成 Echebarria 的 `U` + 稀合金自由能形式，然后直接套用现成的前置因子 | 要重写 `f_loc`、改 IC/后处理、重跑 C1 验证；但之后 C4 变成配置改动 |
| **(ii) 自己推导** | 对本算例的 `f_loc` 做薄界面渐近分析，导出对应的抗截留通量 | 纯理论工作，数天，且容易出错 |

**倾向 (i)**：它把"一个推导任务"变成"一次形式改写 + 一个现成部件"，
而且改写后的模型更接近文献标准，论文里也更好交代。

#### ⚠️⚠️ 但路线 (i) 也不能直接照搬 —— 而且发现了更深的问题

**问题一：Echebarria 是单界面模型，我们是多晶。**
`AntitrappingCurrent` 的前置因子是在 **单个 `phi`** + 无量纲过饱和度 `U` 下推出来的；
我们有多达 8 个 `η_i`。把 η 换成单个 φ 会**摧毁晶粒结构**，不可接受。
⇒ 要做多晶版本，需针对本算例的 `f_loc` 重新做薄界面渐近 —— 仍是研究工作。

**问题二（更根本，2026-09-18 动态测量发现）：尺度分离。**

动态测量（1D 定向凝固，生产分辨率）跑到 `end_time=3e-5 s` 时：
```
c_max = c_min = 0.03607586   ← 完全没有分凝（逐位相同）
界面只移动了 2 µm（0.6 m/s × 3e-5 s 本应移动 18 µm）
```

**原因不是网格，是时间尺度：**
```
溶质在弥散界面内的特征时间  W²/D = (4 µm)² / 2.5e-9 m²/s  ≈ 6.4e-3 s
LPBF 的凝固过程时间                                        ≈ 6.5e-4 s
```

**⇒ 溶质在整个凝固过程里连界面宽度都扩散不过去。**
物理上溶质响应时间是 `D/V² ≈ 1.4e-8 s`，模型把它拉长到 `W²/D ≈ 6.4e-3 s`
—— **放慢约 10⁵ 倍**。这解释了 C1 验证里分凝只有 0.7%。

**⇒ 这解释了为什么"把 end_time 调大"救不了**：要等到 `6.4e-3 s`，界面早已移出 3.8 mm。

**⇒ C4 的性质：不是"界面太宽"这一条，而是模型把溶质的整个动力学放慢了 10⁵ 倍。**
抗截留项只能修正**渐近意义下**的领头阶误差，而 `W/(D/V) = 480` 说明我们**根本不在渐近区**。
**⇒ C4 需要的是定量（薄界面）相场模型，是研究工作，不是配置改动。**

**当前可选的处置**（按可行性）：
1. **如实声明局限**：在论文里给出 `W/(D/V) ≈ 480` 与 `W²/D` vs 过程时间的对比，
   说明本模型的微观偏析**只有定性意义**，不给定量预测
2. **改用有效分配系数** `k(V)`（Liu & Wang 2019 的做法）：绕开弥散界面的动力学，
   但需要局部界面速度 V，且 `V_D` 的取法极度敏感（见 §4.3）
3. **做定量相场改写**：真正的修法，研究工作量，且会牵动 C1/C2 的全部验证

**Aziz 模型**：`k(V) = (k_e + V/V_D)/(1 + V/V_D)`，`V_D = D_L/a0`
**⚠ 结论对 `a0` 的取法极度敏感**：`a0=0.289 nm` ⇒ V_D=41.5 m/s（几乎无截留）；
`a0=3 nm` ⇒ V_D=4.1 m/s（截留显著）。**论文里必须明确声明 `a0` 的取法。**
且**Ti64 在 ~1 m/s 下没有实验 k 数据**，所有结论都是模型推断。

### 4.4 C2 详细方案

**文献结论：`A_ani` 在 β-Ti 体系里从未被定量测量过**，找不到可引的值
（最接近的 Wu 2012 用的是开关参数 0/1，不是连续强度）。
**⇒ 只能标定。** 做法：
1. 灵敏度扫描 `A_ani ∈ {0, 0.3, 0.7, 1.0}`，量织构强度与晶粒长宽比
2. 与 LPBF Ti64 实测织构（`<100>` 纤维织构强度）比对，定出 `A_ani`
3. 论文里明确写成"标定参数"并给出标定曲线

**顺带**：`Q = 3.234 eV` 是**唯一有明确出处的参数**（Semiatin 1996, Acta Mater. 44:1979,
312 kJ/mol）；但 **`M0 = 232 m⁴/(J·s)` 查无出处**，需从 Semiatin 1996 的
`(n=2, k=1110, Q=312 kJ/mol)` 反推，或标注为标定值。

### 4.5 C0 + C3 详细方案（最大的一块，放最后）

**问题**：形核需要 GrainTracker 的 remap，而 remap 会改变晶粒所占的序参量；
本算例的取向**硬编码绑在序参量上**，remap 一次取向就被改掉。

**B0a 实测已澄清**：`reserve_op` 是**【永久槽位】**——每个保留 op 承载 1 个形核晶粒、
取向固定、永不被 remap。⇒ **路径 A 的形核次数上限 = 保留 op 个数**，
而 LPBF 等轴晶区可能有 5–15 个晶粒 ⇒ `op_num` 要 16–26 ⇒
表达式规模超线性增长（§B2 已量化）**不可接受**。

**⇒ 结论：路径 A 不 scale，必须走路径 C**（写 per-grain 取向的 C++ Material）。
**但路径 C 有一个巨大的附带收益**：取向改为按晶粒 ID 索引后，
**"11 个晶粒挤在 8 个序参量上"这个问题自动消失**（共用 op 不再意味着共用取向）
⇒ **B2 不必做**，op_num 可以保持小。

**路径 C 的实现要点**（依据 `ComputePolycrystalElasticityTensor.C:63-89` 的成熟模式）：
```cpp
const auto & op_to_grains = _grain_tracker.getVarToFeatureVector(_current_elem->id());
// 逐 op 拿到它当前承载的 grain_id，再 _euler->getEulerAngles(grain_id) 取取向
// 对每个活跃 (m,n) 对：Δθ -> σ_mn (Read-Shockley) / M_mn (位错模型)
//                      -> Moelans Alg.1(σ_mn, mu_qp=9e5) -> kappa_mn, gamma_mn
// 再乘 Val_mn 加权平均；L 额外乘 1+A_ani*(2*align4-1)
```
**必须提供导数**：`ACInterface` 无条件索取 `dL/dop`、`d2L/dop2`、`dkappa_op/dop`，
所以要用 `DerivativeMaterialInterface` 手工写（**拿不到时 MOOSE 会静默填零、不报错**，
见 §3.1 的死结③）。预计 **~250 行 C++ + 重编译 phase_field**，1–2 周含调试。

## 附录 A【配置坑，会反复咬人】起始 `dt` 必须给 ~1e-7

> （放在文末是因为它是通用的操作坑，不属于某一阶段。**写任何新算例前先看这条。**）

**现象**：`dt=1e-6` 或 `4e-6` 起步时，**首步反复失败**——牛顿爬行十几到二十几次迭代不收敛

而把首步降到 **5e-7** 就正常收敛。

**这不是物理问题，是配置问题。** 正确做法：`[TimeStepper]` 的 `dt` 起始设 **1e-7**，
让 `IterationAdaptiveDT`（`growth_factor=1.5`）自己爬升到 `dtmax`。
代价约 9 个额外小步，换来不再有失败的首步。

**这条已影响过**：`bench_full`（首步 47 分钟白烧）、`mpi_scale`、`diag_scaling` —— 三者都因此重启过。
**以后写任何新算例，起始 `dt` 一律 1e-7。**
