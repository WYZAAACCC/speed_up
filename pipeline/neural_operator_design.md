# 逐面神经算子：输入输出设计

> 2026-09-17 版。基于用户的要求：
> 输入应以"某个面两侧的两个晶粒的数据 + 该面自身的数据"为基础；
> 每个晶粒的信息要定义清楚，保留问题范围内的完整信息。

---

## 一、先明确它是什么、不是什么

**是**：一个**局部的**算子，在每一个时间步、对**每一个面**单独调用一次，权重在所有面之间共享。

**不是**：作用在整个晶粒网络上的全局算子（那是 GINO / 几何算子那一类）。

类比：**就像有限体积格式在每个面上求数值通量**那样，只不过这个"求值"是学出来的。

---

## 二、符号约定

| 符号 | 含义 |
|---|---|
| $f$ | 一个面（晶粒 $i$ 与 $j$ 之间的晶界接触区） |
| $A_f$ | 面的面积（2D 是长度） |
| $\Gamma_f$ | 面上的**溶质过量**，$\int_{\text{面区}}(c-c_{\text{bulk}})\,\mathrm{d}V$ |
| $g$ | 一个晶粒；$V_g$ 体积、$c_g$ 体相浓度、$M_g=c_gV_g$ 溶质含量 |
| $\Delta t$ | 时间步长 |

**守恒量的分布**：总量 $=\sum_g c_g V_g+\sum_f \Gamma_f A_f$

---

## 三、输入（三组，按用户提的结构组织）

### A. 面自身的数据

| 特征 | 无量纲化 | 说明 |
|---|---|---|
| 面积/长度 $A_f$ | $A_f/L_{\text{ref}}^{d-1}$ | $L_{\text{ref}}$ 取平均晶粒尺寸 |
| 溶质过量 $\Gamma_f$ | $\Gamma_f/(c_{\text{ref}}A_f\delta_{\text{ref}})$ | |
| 迁移速度 $v_f$ | $v_f\delta_{\text{ref}}/(M_{\text{gb}}\gamma)$ | 由面位置的时间差分得到 |
| 曲率 $\kappa_f$ | $\kappa_f L_{\text{ref}}$ | 2D 是线的曲率；3D 是两个主曲率 |
| 法向 $\hat n_f$ | — | 分量本身就是无量纲 |
| 存在时长 $t_f$ | $t_f/\tau_{\text{ref}}$ | 面"年龄"，帮助判断是否刚生成 |

### B. 两侧晶粒的数据（对 $i$ 和 $j$ 各一份，**有序**）

用户特别强调"每个晶粒的信息需要定义清楚，要能保留完整的需要的信息"。
下面是我认为**完整且必要**的清单：

| 特征 | 无量纲化 | 为什么需要 |
|---|---|---|
| 体积 $V_g$ | $V_g/L_{\text{ref}}^d$ | 晶粒大小决定曲率驱动力 |
| 体相浓度 $c_g$ | $c_g/c_{\text{ref}}$ | 化学势差的主要来源 |
| 溶质含量 $M_g=c_gV_g$ | $M_g/(c_{\text{ref}}L_{\text{ref}}^d)$ | 直接与守恒记账对应 |
| 质心 $\mathbf{x}_g$ | $\mathbf{x}_g/L_{\text{ref}}$ | 算晶粒间距离 |
| **配位数** $N_g$ | — | 晶粒在拓扑网络中的位置 |
| **形状因子** $V_g/A_g^{d/2}$ | — | 等轴程度；$A_g$ 是晶粒总表面积 |
| **面的占比** $A_f/A_g$ | — | 这个面在晶粒表面的分量 |
| 面心相对质心的方向 | 单位向量 | 面在晶粒的哪一侧 |

> **为什么"面的占比"和"配位数"重要**：它们把**局部面**和**晶粒整体**连起来。
> 同一个面的演化，取决于它背后的晶粒有多大、有多少别的面在跟它抢溶质。
> 没有这两个量，算子就只能看到孤立的面。

**将来加各向异性时补**：取向（Euler 角）、取向差、晶界类型。

### C. 全局/环境

| 特征 | 说明 |
|---|---|
| 时间步 $\Delta t$ | **必需**——算子预测的是"一个时间步内的累积量"，不是速率 |
| 温度 $T$ | 影响扩散与迁移率 |
| 体扩散系数 $D$ | |
| 晶界宽度 $\delta$ | |

## 四、输出与守恒（设计的关键）

### 采用：预测交换通量

算子对每个面输出**两个通量**：

$$J_{i\to f},\qquad J_{j\to f}$$

含义：一个时间步内，从晶粒 $i$（或 $j$）流入面 $f$ 的溶质量（可正可负）。

### 装配时守恒自动成立

$$\Delta(c_iV_i)=-\!\!\sum_{f\in\text{faces}(i)}\!\!J_{i\to f}
\qquad
\Delta(\Gamma_fA_f)=J_{i\to f}+J_{j\to f}$$

**每一个 $J_{i\to f}$ 在晶粒一侧是流出、在面一侧是流入，求和时精确抵消。**

总量严格守恒，**与网络预测精度无关**。这是通量形式的根本好处。

### 一个必须处理的细节：面积在变

面 $f$ 的面积 $A_f$ 会随时间变。所以：

$$\Delta\Gamma_f=\frac{J_{i\to f}+J_{j\to f}-\Gamma_f\,\Delta A_f}{A_f}$$

面积变化 $\Delta A_f$ 由**晶粒几何求解器**给出（已知量），不是学出来的。
**但注意：$-\Gamma_f\Delta A_f$ 这一项本身会改变面上的溶质量——面缩小时，它携带的溶质被"挤"出来，必须计入。这一项是几何的、可解析计算的，不需要学。**

---

## 五、一个重要的归纳偏置：反对称性

交换 $i$ 和 $j$，物理不变，只是通量方向反过来：

$$J_{j\to f}\big|_{\text{交换后}}=-\,J_{i\to f}\big|_{\text{交换前}}$$

**实现方式**：训练时做**数据增强**——把每个样本的 $(i,j)$ 对调、标签取负，作为额外样本。

这比在网络结构里硬编码反对称更简单，而且效果等价。

输入里凡是区分 $i$ 和 $j$ 的量都**有序地**给出（$i$ 在前、$j$ 在后），网络自己学出反对称。

## 六、关于"相邻算子之间交互信息"（用户的想法）

> 用户的判断：初始实现先不做，等 3D 打通、算子有效性验证之后再说。

**我完全同意，并且补充理由**：

1. **会让"逐面独立调用"的定位消失。** 现在的卖点是算子只依赖局部状态、可复用、可并行。一旦引入邻面交互，就变成了一个小型的图网络，调用成本与邻域大小相关，退化成 GrainGNN 那一类。
2. **第一次实现时数据量不够验证它的收益。** 引入交互会显著增加参数量和过拟合风险。
3. **但它是很好的"后续工作"**：如果实验表明**误差集中在面的网络连通性强的区域**（比如三叉线附近），那就是引入交互的明确动机。

**建议的做法**：第一版实现后，**按"面的配位数"和"邻近面的状态差异"分层统计误差**。如果误差确实在网络密集处更大，就有数据支撑去做交互版本。

## 七、第二块：转移算子

### 职责比最初设想的更广

**不只是"面消失"，还有"面出现"——两者必须配对。**

```
面消失 → 它携带的 Γ_f·A_f 去哪？
面出现 → 它的 Γ_f·A_f 从哪来？
```

守恒要求这两者必须配套。**只处理消失不处理出现，总量就对不上。**

（这一点是在闭环回放时才暴露出来的：滚动过程中面的集合本身会波动，
新面若不给初值，状态字典里就找不到它。）

### 输入输出

**输入**：消失/出现面上最后（或最初）时刻的 $\Gamma_fA_f$、两侧晶粒 $i,j$ 的状态、以及 $i,j$ 的邻居情况
**输出**：分配比例（给 $i$、给 $j$、还是给更远的邻居）

**守恒约束**：分配比例之和必须为 1，**严格**。

### "正确答案"从哪来

从相场数据提取——面消失前后，其上的溶质**实际流到了哪里**；
面出现前后，其上的溶质**实际从哪里来**。

这正是相场方法"免费"做到、而显式方法必须显式回答的事。

### 与神经算子的区别

| | 神经算子 | 转移算子 |
|---|---|---|
| 处理什么 | **连续演化**（面在，慢慢变） | **离散事件**（面没了/新来，一次性） |
| 触发时机 | 每个时间步、每个面 | 只在拓扑事件发生时 |
| 时间尺度 | 平滑 | 瞬态 |

## 八、待落实的问题

1. **量的定义需要和提取管线对齐**：上面的 $\Gamma_f$、$A_f$、$c_g$、$V_g$ 都要能从 Exodus 精确算出来（`extract.py` 已有部分）
2. **无量纲化的参考量**（$L_{\text{ref}}$、$c_{\text{ref}}$、$\delta_{\text{ref}}$）要定下来
3. **面的"迁移速度"**如何从离散的时间序列稳健地算出来（面在动、形状在变）
4. **数据量**：训练需要多少面-时间步样本？现在一个算例能产出多少？
