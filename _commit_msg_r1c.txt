## 结论（先说结果）

**① `reinit_iters = 100` 确实远超必要，而且在"输入已 SDF"时是净有害的。**
子代理的受控扫描（`_w2_r1reinit_iters.log`，N=96，REF=iters 200）：

| iters | 用时 s | 输入 med\|∇d2\| | 输出 med | **region 翻转** | \|Δ−REF\| |
|---|---|---|---|---|---|
| 5   | 0.80 | 0.9945 | 0.9825 | **0** | 2.671 |
| 20  | 3.14 | 0.9945 | 0.9294 | **0** | 2.093 |
| 36  | 5.30 | 0.9945 | 0.9273 | 2 | 1.534 |
| **100**（生产） | 15.04 | 0.9945 | 0.9916 | **23** | 0.238 |
| 200 | 30.86 | 0.9945 | 0.9939 | 33 | 0 |

⇒ 输入本来就在 1±0.6% 内（`reinit_skip_tol=0.05` **本来就该跳过它**）。
迭代越多 ⇒ **零等值面被推得越远**（`dmed` 从 −0.037 走到 −0.655 胞）、翻转越多。
⇒ 这正是代码自己写过的记账："已经够 SDF 就不要动它 —— 只会带来害处而几乎没有好处"。

**② 子盒（包围盒）路线：实测否决。** 见下。

## 子盒路线 —— 一次完整的"推理 → 实测 → 否决"

**我的推理**：Sussman 的迎风依赖锥**指向零等值面内部**，而回写掩模本来就是
`|d2| ≤ band·dx` ⇒ 带外的迭代结果**根本不被使用** ⇒ 只在"带 + 余量"的子盒里迭代
应当**逐位相同**，代价按子盒体积缩小。

**实测（`_r1_bbox_margin.py`，真实引擎状态，逐位判据）**：

| margin | 逐位相同的配对数 | 体积占比 中位 / 最大 |
|---|---|---|
| 0  | 1/4 | 0.557 / 1.000 |
| 4  | 1/4 | 0.705 / 1.000 |
| 8  | 2/4 | 0.839 / 1.000 |
| 16 | 3/4 | 1.000 / 1.000 |
| **32** | **4/4** | **1.000 / 1.000** |
| 64 / 128 / 203 | 4/4 | 1.000 / 1.000 |

⇒ **最小充分 margin = 32 胞，而那时包围盒已经等于全盒** ⇒ **省不到任何东西**。

**我原来错在哪**：只算了"特征线 1 胞/迭代"，但 `upwind_grad2` 的**数值依赖锥是每迭代 ±2 胞**
（`Dm2[i]` 用到 `phi[i−2..i+1]`、`Dp2` 用到 `phi[i+2]`）⇒ `iters=100` 时半径 ≈ 200 胞。
**这是一个负结果，如实登记**（`AGENTS §3.16`：传承结论也要能算数才算数）。
⇒ `reinit_bbox` 默认保持 **False**；代码留着，供"已知近似模式"用。

## ★ 自查抓到的第二个我自己的 bug：子盒路径的**别名**

第一版子盒路径写的是 `phi[bbox] = out; return phi` —— **原地改了调用者传进来的数组**。
而调用者 `reinitialize()` 写的是
```python
dn = self.sussman_reinit(d2, bbox=_bbox)
corr2 = np.where(near, dn - d2, 0.0)
```
⇒ `dn is d2` ⇒ **`corr2 ≡ 0`**（修正量被自己减掉了），且**不报错**。
修法：子盒路径**必须返回新数组**（全域路径返回的本来就是新数组 —— `_sussman_core`
内部 `phi = phi/_gm` 会新建）。这正是"契约不一致"型静默 bug。

## 顺带的两处结构改动（**逐位不变**）

* `sussman_reinit` 的迭代循环抽成**唯一实现** `_sussman_core`，
  "全域 / 子盒 / 单线程 / 多线程"四条组合**共用同一段代码**。
  ⚠ 记账：`windowB_par.ParCtx.sussman_reinit` 最初在这里**复制**了一份循环、
  且**只有并行路径**支持子盒 ⇒ 那会让**线程数变成物理参数** ⇒ 已改为**纯委托**。
  （与 `AGENTS §3.24`「改一半比不改更危险」同类。）
* `reinitialize()` 增加**只为记账**的墙钟计时（`_reinit_wall_last` / `_reinit_wall_total`
  / `_reinit_pairs_last`），不改变任何数值或分支。
